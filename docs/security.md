# セキュリティ: 保証範囲・範囲外・脅威モデル

本言語のコンパイラ・ランタイム・LLM の proxy・LSP が**何を保証し、何を保証しないか**をまとめる（NFR-001 / NFR-005、AC-007）。脆弱性の報告の窓口と範囲は ADR-0028（Proposed）と、公開時に置く `SECURITY.md`。この文書は公開準備の T11（`docs/plans/release.md`）のセキュリティの見直し（2026-11-11、Fable）の結果を元にしている。

## 1. 脅威モデル

| 信頼するもの | 信頼しないもの |
|---|---|
| プログラムのソース（利用者が書いたもの）、コンパイラ、ランタイム、利用者が設定した環境変数（`WYS_*`）、`cmd:` で指定したプロバイダ | **LLM の出力**（テキスト、ツールの呼び出しの名前と引数、`usage` などのメタデータ）、**ツールの戻り値**、**プロバイダの応答の形**、プログラムに入る外部の値（`Unknown`、`parse_json`） |

守りたいもの:

- **権限の境界**（AC-007）: LLM がツールの呼び出しを通して、agent に与えていない Capability（`io` を除く。下の 3 章）を使えないこと。承認が要るツールが承認なしで動かないこと。予算（回数・トークン・費用・時間）を超えないこと。
- **秘密情報**（NFR-005）: API キーがランタイム・生成した実行ファイル・記録・監査・トレース・エラーの文面に出ないこと。プロンプトと応答の本文が、明示の opt-in なしにログに出ないこと。
- **メモリ安全性**（MEM-005 / NFR-001）: `docs/design/memory-model.md` 3 章の保証範囲。

## 2. 保証していること

### 2.1 Capability（AI-004、ADR-0023）

- 実行時の Capability は、根では `WYS_CAPABILITIES` で**縮めるだけ**（広げられない。未知の名前は無視、空はすべて外す）。`@agent` に入ると、外側との**積**になる。
- ツールを実行する前に、一覧 → Capability（ツールの `uses` ⊆ agent の Capability）→ 予算 → 承認の順に検査する。
- 実行時の入口でも再検査する: `llm_generate`、Python の入口（`py_import` / `getattr` / `call`）、`exit`。拒否は監査 `capability_denied`。
- `spawn` した子タスクは親の agent コンテキストを引き継ぐ。記録の再生（`replay:`）でも、ツールは同じ検査を通って実際に動く。
- 静的な検査（ADR-0014 / ADR-0024）: `@tool` の `uses` は必須で、本体（推論した Effect を含む）が宣言に収まることを E1102 が検査する。`@agent` の `uses` ⊆ `capabilities`（E1405）、`capabilities` ⊆ 自身の `uses`（E1406）、同じ名前のツール（E1404）、負の予算（E1402）。

### 2.2 ツールの引数と JSON（AI-002）

- ツールの引数は `parse_json` → `validate[T]` を通ってから本体に渡る。`parse_json` は深さ 128 で打ち切り、重複したキーを拒む。型の取り違え（`2.0` を `int`、`true` を `int` など）、欠けたフィールド、オブジェクトでない引数は拒否する。宣言にないキーは無視する（`docs/design/ai-sdk.md` 4.3）。
- プロバイダの応答の 1 行は 16 MiB まで、再帰の上限つきで読み、壊れた行や長すぎる行は `Err(kind="provider")`（クラッシュしない。メモリを使い切らない）。

### 2.3 承認（AI-005）

- 既定（`WYS_APPROVAL` 未設定・空）は `deny`。未知の値は `Err(kind="approval")` で閉じる。
- `prompt` は stderr に問いを出し、stdin から 1 行読む。`y` / `yes` だけが許可、空行とそれ以外は拒否、EOF は `Err(kind="approval")`。**問いに出すツール名と引数の、端末を操作する文字（C0 / DEL / C1）・双方向制御・見えない文字は `\u{..}` にエスケープし、長くても切らない**（#144。切ると、承認する内容を切った後ろに隠せる）。

### 2.4 予算（AI-006）

- スタック上のすべての agent に数え、どれかの上限を超えたら止める（内側の agent が外側の残りを超えない）。
- プロバイダの `usage` は 0 以上の整数だけを受け取る。壊れた数の応答は `Err(kind="provider")` で、正しいほうの数と正しい `cost_usd` は数え、トークン数・費用が分からないときは以後の呼び出しを超過として扱う（閉じる方向。#143）。`cost_usd` は有限で 0 以上だけを受け取る。
- 記録とモックの `latency_ms` は 0〜1 日に丸め、時計の加算は飽和させる（#143）。

### 2.5 秘密情報とプライバシー（NFR-005、ADR-0023 論点 16、ADR-0025）

- `ANTHROPIC_API_KEY` を読むのは proxy（`wys llm-proxy`）だけ。ランタイム・生成した実行ファイル・記録には現れない。proxy のエラーの文面は HTTP の状態と API のエラーの種類・文面だけで、ヘッダとキーは含まない。proxy は要求と応答をログに書かない。
- 監査（`WYS_AUDIT`）とトレース（`WYS_TRACE`）は、既定では本文（system プロンプト、メッセージ、応答、ツールの引数と戻り値）を含まない。トレースの本文は `WYS_TRACE_CONTENT=1` の明示の opt-in。
- 記録（`WYS_LLM_RECORD`）には本文が入る（利用者が名指しで作るファイル）。権限は 0600 で、既にあるファイルやシンボリックリンクは外してから新しく作る（リンクの先を書き換えない。#145）。監査とトレースのファイルは `O_NOFOLLOW` で開く。
- proxy と `cmd:` のプロバイダは、シェルを通さずに起動する（空白や引用符で引数を注入できない）。`/` を含むパスは実在と実行の権限を確かめる。

### 2.6 一時ファイル（#145）

- `wys build` / `run` / `test` / `eval` の一時のファイル（中間のオブジェクト、生成した実行ファイル、eval のトレース）は、一意の名前の 0700 のディレクトリ（既にあれば作らない）の中に作る。clang には引数を個別に渡す（ファイル名で注入できない）。

### 2.7 LSP（ADR-0026）

- `file://` の URI だけを扱い、ほかは無視する。プログラムをビルド・リンク・実行しない（解析だけ）。
- 解析は大きなスタックの別スレッドで行い、パニックでサーバーが落ちない。スタックの溢れはパーサの入れ子の上限（E0107、64 段）で防ぐ。壊れた要求の引数は `InvalidParams`。

### 2.8 メモリ安全性（MEM-005、`docs/design/memory-model.md` 3 章）

- `unsafe` は `wys_runtime` と `wys_runtime_python` の 2 クレートだけ（ワークスペースは `unsafe_code = "deny"`）。用途は C ABI、ヒープオブジェクト、タスクのスタック（`mmap` とガードページ）とコンテキストの切り替え、CPython の Stable ABI。
- リストの添字は負を含めて検査し、整数のオーバーフローとゼロ除算は実行時エラー。Python の名前の NUL は失敗に、外部からの不正な UTF-8 は置き換える。
- Conformance は Debug・Release（-O2）・AddressSanitizer の 3 モードで回し、終了時の生存オブジェクト数を検査する。

## 3. 保証しないこと（範囲外）

- **`io` は実行時に強制しない**。`print` などの `io` は静的な検査（`uses io`）だけで、`WYS_CAPABILITIES` から `io` を外しても `print` は動く。実行時に強制するのは `llm` / `python` / `exit`（`docs/design/ai-sdk.md` 7.2）。
- **Python のコードはサンドボックスではない**（ADR-0018）。`python` の Capability を持つ agent は、Python を通して何でもできる。また、Python の値の変換（`list` のサブクラスの `__len__` / `__getitem__`）と解放（`__del__`）では利用者の Python が動き得る。変換は型検査で `python` の Effect を要求するが、解放は Effect を要求しない（終了時など）。
- **利用者のプログラムの誤り**、利用者が指定した `cmd:` のプロバイダ、LLM の出力の内容そのもの（誤り・偏り）は範囲外。
- 監査の `detail` には、スキーマの検証の失敗の理由（LLM が書いたキーの名前を含み得る）と、LLM が指定したツールの名前が入り得る。本文そのものは入らない。
- `llm_generate` を使うプログラムには、コンパイラの絶対パスが埋め込まれる（proxy を探すため。`wys dump-llvm` で見える）。配布する実行ファイルからビルドした環境のパスが読める。別の環境では `WYS_LLM_PROXY` か `PATH` で proxy を指定する（ADR-0030 論点 8）。
- AddressSanitizer はランタイムのライブラリ（Rust）自体を計測していない（生成コードだけ）。
- Windows は対象外（ADR-0029）。

hardening の残り（ランタイムの ASan / Miri）は #146。`dict` の文字列のキーのハッシュはプロセスごとに乱数の種を持つ SipHash、プロバイダの応答の 1 行は 16 MiB まで（#146）。
