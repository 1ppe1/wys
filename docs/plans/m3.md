# M3 実行計画（承認済み: 2026-11-04）

Fable（計画）が作成し、ユーザーが承認した。ARC は IR の独立パスで挿入する（ユーザー決定）。進捗は各タスクの PR と `docs/roadmap.md` で管理する。

## 方針

- 参照型にする順番は `str` → `list[T]` → `dict[K, V]`。**レコードと Union は M3 では値型のまま**（不変なので意味は変わらない、ADR-0009）。参照型のフィールドや要素は持てるようにする。
- **ARC は IR 上の独立したパス**（挿入 → 検証 → 冗長な組の除去）で入れる。各一時値に所有の種類（+1 所有、ローカルからの借用、可変な場所からの借用、不死）を付け、memory-model 2.2 の規則（借用の安全条件を含む）をそのまま規則にする。
- `str` はポインタ1語。ヘッダは参照カウントと長さ。文字列リテラルとコマンドライン引数は不死（参照カウント −1）。
- `list[T]` の要素は箱に入れない。ランタイムは要素の大きさ付きのバッファだけを持ち、要素の参照カウント操作（drop glue）は生成コードが行う。IR の型は、Union と同じく使われた具体的な型だけを登録する。
- 解放が必要かどうか（`needs_drop`）や、型ごとの解放処理は、型を登録するときに計算して表に持つ（M2 の教訓: 深い型を再帰でたどると指数的になる）。
- 正しさの検査は3つ: ARC の検証器、デバッグ用ランタイムの生存オブジェクト数（終了時に 0 でなければ失敗）、AddressSanitizer（`WYS_SANITIZE=address`）。M3a では循環参照を作れないので、生存数を厳密な合否の基準にできる。

## 分割の判断基準

T4b の完了時点で5週を超えた、または T3 の検査で IR の設計変更が必要になった場合、**M3a = T0〜T4b**（`str` / `list` / ARC / ASan / Release）で出口判定する。M3a だけで Phase 1 の完了条件と MEM-001/002/005、COMP-005、NFR-006 を満たせる。**M3b = T5〜T10**。

## 出口判定（2026-11-05、T11）

**判定（ユーザーが 2026-11-05 に承認）: Phase 1 の完了条件と、M3 の完了条件（MEM-001 / MEM-002 / MEM-005、COMP-005、NFR-006）を満たした。** 計画にあった Move 最適化（冗長な retain / release の組の除去）は、どのタスクにも割り当てておらず、実装していない。正しさには関係しない最適化なので、M4 に持ち越す。M3a / M3b への分割は不要だった（T4b の完了時点で5週以内、IR の設計変更なし）。

最終的な Conformance ケースは `lang/` 76、`types/` 92、`syntax/` 16、`diagnostics/` 6、`explain/` 5、`modules/` 18、e2e は 31。CI（`./scripts/ci.sh`）は、macOS arm64 と Linux x86_64 で Debug・Release・AddressSanitizer の3つのモードを通す。
