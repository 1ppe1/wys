# M4 実行計画（承認済み: 2026-11-05）

Fable（計画）が作成し、ユーザーが承認した。ADR-0018 は Accepted（2026-11-05）。Python → 本言語の値は `Unknown` ではなく型ごとの変換メソッド（`to_int` など）で返す（ADR-0018 論点 9・11。下の方針の記述より優先する）。ADR の番号: `float`（T12）を ADR-0019 にしたので、`async` のモデル（T9）は ADR-0020（2026-11-05）。承認時の決定: M4a（FFI）/ M4b（`async`）の分割と PoC3 の判定基準は草案のとおり、CPython の C API は手書きの `extern "C"`（Stable ABI の関数だけ）、`float`（T12）は M4 に入れて T7 の前に行う。M4 は Phase 2（AI ネイティブ MVP）の最初のマイルストーンで、範囲は CPython FFI（未決定事項 8）と `async`（LANG-008）。進捗は各タスクの PR と `docs/roadmap.md` で管理する。

## 方針

- **PoC3 を最初の2週間に置く。** ロードマップのリスク表「CPython FFI: 往復呼び出しと例外伝搬が2週間で動かない → ゼロコピーを Phase 3 へ回し、対応する Python のバージョンを1つに固定」に合わせ、期限と成功・中止の基準を先に決めて試作する（T1）。ゼロコピー（INTEROP-003）は**最初から M4 の範囲外**にし、Python のバージョンも**最初から1つ（3.14、GIL あり）に固定**する。転換基準に当たったときの代替案は T1 に書く。
- **FFI の方向は埋め込み（embedding）。** 本言語の実行ファイルが CPython を初期化して使う。Python 側から本言語の実行ファイルを拡張モジュールとして読み込む方向と、Python → 本言語のコールバックは M4 では扱わない（関数値 E0213 がないため）。
- **Python を使わないプログラムの実行ファイルは変えない。** Python のランタイムは別の staticlib（`crates/wys_runtime_python` → `libwys_runtime_python.a`）にし、`python` Effect を持つ組み込みを使うプログラムをビルドするときだけ、それと `libpython3.14` をリンクする。AC-004 の「依存は OS 標準のみ」の e2e はそのまま通す。
- **Python のオブジェクトは不透明なハンドル。** 本言語の型 `PyObject`（名目的な参照型）は、本言語のヒープオブジェクト（ADR-0012 のヘッダ + `PyObject*` 1語）で Python の参照を包む。retain / release は既存の ARC のまま、解放処理（drop glue）が `Py_DecRef` を呼ぶ。これで ARC パス・検証器・生存数の検査（102）・`wys explain` を変えずに済み、Python の参照カウントと本言語の参照カウントの「二重管理」を1か所（解放処理）に閉じ込める。
- **境界の変換はコピーだけ、Python → 本言語の値はスカラーに限り `Unknown`。** 本言語 → Python は `int` / `bool` / `str` / `None` と、それらを要素に持つ `list` / `dict` を新しい Python オブジェクトに写す。Python → 本言語は、スカラーなら `Unknown`（ADR-0011 の `match` で検証する既存の規則）に、それ以外はハンドルのまま返す。`Unknown` に `list` / `dict` を足す拡張（ADR-0011 の見直し条件）は再帰型を要するので、再帰レコード・`weak` と一緒に M5 の前（JSON とスキーマ検証を入れるとき）に決める。
- **例外は値として返す（AC-010）。** Python を呼ぶ組み込みはすべて `Result[..., PyError]` を返す。例外は `PyError`（レコード。例外の型名・メッセージ・あればトレースバックの文字列）の `Err` にし、パニックにはしない。変換の型不一致（Python が `float` やオブジェクトを返した、など）も `Err`。パニックになるのは Python の初期化に失敗したときだけ（`runtime error: cannot initialize Python ...`）。
- **GIL は本言語のスレッドが起動時に取得し、手放さない。** 本言語はシングルスレッドなので、これで INTEROP-002 の「スレッド制約」を満たす。M4b の `async` も単一スレッドの協調的な実行にし、GIL の解放は要らない。free-threaded ビルド（`Py_GIL_DISABLED`）は対象外。
- **Effect は `python` を1つ足す。** Python を呼ぶ組み込みはすべて `python` を要求する。`python` は「任意の副作用を起こし得る」ことを表し、M5 の Capability Runtime は Python の内側を強制できない（サンドボックスではない）と ADR に明記する。`ffi`（C の FFI）は M4 では足さない。
- **`async` は M4b として同じ計画に入れるが、M4a（FFI）だけで出口判定できるようにする**（下の「分割の判断基準」）。モデルは ADR-0020 で決める。推奨は、コンパイラを変えずに済むランタイムのスタックフル・コルーチン（単一スレッド、協調的）。memory-model 2.2 の「`await` の前に借用の安全条件を再確認する」は T10a で行う。
- **持ち越しは、ADR のレビュー待ちの間に片付ける。** Move 最適化（T3）と AST のメソッド呼び出しの印（T4）は PoC3 と ADR-0018 のレビューに依存しないので、並行して進める。T4 は `PyObject` のメソッド（`h.attr(...)`）を入れる T6 の前に終える。
- 正しさの検査は M3 と同じ3つ（IR の検証器、終了時の生存数、AddressSanitizer）を Python を使うケースにも適用する。ASan モードで CPython を動かせるかは PoC3 で確かめ、無理なら Python のケースだけ ASan を除外して理由を書く。性能は往復と初期化の時間の絶対値だけ記録する（倍率は書かない）。

### PoC3 の判定（T1）

期限は 10 営業日。**成功**の基準（すべて満たす）:

1. 本言語が生成した実行ファイルから、macOS arm64 と Linux x86_64（CI）の両方で Python 3.14 を初期化し、`json` / `math` を import して関数を呼び、`int` / `str` の引数と戻り値を往復できる。
2. Python の例外（`ValueError`、`ZeroDivisionError`、`ImportError`、`AttributeError`）を捕捉して、型名とメッセージを本言語側の値にして返せる。プロセスは落ちず、終了時の生存数の検査（102）を通る。
3. Python を使わない実行ファイルの依存関係が変わらない（AC-004 の e2e が通る）。
4. ASan モードで Python のケースを動かしたときの挙動が分かっている（通る、または除外する理由と手順）。
5. 初期化の時間と往復の時間を `docs/poc/poc3-results.md` に絶対値で記録した。

**転換**の基準（ロードマップのリスク表）: 10 営業日で 1 または 2 が macOS arm64 で動かない。そのとき、ゼロコピーは既に範囲外、バージョンも固定済みなので、次の順で範囲を狭める。

- (a) Linux だけで失敗 → M4 の FFI は macOS arm64 だけを対象にし、Linux の CI では `python/` のケースを飛ばす（NFR-006 の対象環境は変えない。Linux の FFI は Phase 3）。
- (b) 1 が macOS でも動かない → 埋め込みをやめ、Python をサブプロセスとして起動して JSON を stdin / stdout でやり取りする橋渡しを M4 の暫定にする。INTEROP-001 は「部分合格」とし、埋め込みは Phase 3 で再挑戦する。
- (c) 2 だけ動かない → `PyError` を型名なしのメッセージ1本に縮め、例外の種類の区別は Phase 3 へ。

## 診断コードの帯

E12xx Python FFI（E1201 Python の境界に渡せない型: レコード・`Result`・型パラメータ・未検証の `Unknown`。E1202 `PyObject` / `PyError` を具体的な型が必要な場所で使っている: `print` / 演算 / `==` / `dict` のキー。ヒントで `to_scalar()` と `match` を示す）、E13xx `async`（E1301 `await` が `async def` の外、E1302 `await` の被演算子が `Task` でない、E1303 `async def` の関数を `await` / `spawn` なしで呼んでいる、E1304 `spawn` の引数が `async def` の呼び出しでない）。Effect の `python` は E1101 の一覧に加わるだけで、新しいコードは要らない。E0704 の「ローカル変数とモジュール名の衝突」の用法は T4 で廃止（コードは残す）。

実行時: Python の例外はパニックにしない。パニックは Python の初期化失敗（`runtime error: cannot initialize Python: ...`）だけ。Python が見つからないときの `wys build` はツールエラー（`cannot find Python 3.14 ... set WYS_PYTHON`）で、診断 JSON には出さない。

## 分割の判断基準

**M4a = T0〜T8（FFI）**、**M4b = T9〜T10（`async`）**、T12 はどちらにも入れられる。M4a だけで AC-010、INTEROP-001 / 002 を満たせるので、次のいずれかに当たったら **M4a で出口判定し、M4b は M5 の前の独立したマイルストーンにする**。

1. T1（PoC3）が転換基準に当たった（FFI の縮小に集中する）。
2. T8 の完了時点で開始から 7 週を超えた（ロードマップの「目安期間の 1.5 倍」の規則）。
3. ADR-0020 で IR の状態機械方式を選んだ（規模が L から XL になり、`wys_lower` と ARC パスの変更が要る）。
4. M5 の `docs/design/ai-sdk.md` の設計を先に見ないと `async` の要求（LLM 呼び出し、ツール実行の並行性）が決まらないとユーザーが判断した。

LANG-008 は「`async/await` と `Result`」の2つからなり、`Result` は M3 で合格している。M4a で出口判定する場合、LANG-008 は「部分合格（`Result` のみ）」と記録する。
