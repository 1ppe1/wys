# M5 実行計画（承認済み: 2026-11-05、完了: 2026-11-07）

Fable（計画）が作成し、ユーザーが承認した。承認時の決定: `@tool` / `@agent` はコンパイル時の属性、実プロバイダは別プロセスの `wys llm-proxy`、JSON は `Unknown` の拡張で受け、利用者定義の再帰レコードと `weak` は入れない。ほかの論点（呼び出しの型引数の明示、プロバイダ未設定時はモック、`llm_generate` は `async`、タイムアウトは呼び出しの境界で判定、Capability の名前は Effect と同じで agent の既定は `io` / `llm`、ADR を 0021〜0023 の3本に分けることなど）も本文のとおり。M5 は Phase 2（AI ネイティブ MVP）の2つ目のマイルストーンで、範囲は AI SDK の核（AI-001〜006、AC-006〜008）と未決定事項 9 / 10。issue は #61（本計画）、#62（PoC4・`ai-sdk.md`・ADR）、#63（型付き LLM API とスキーマ検証）、#64（`@tool` / `@agent`）、#65（Capability・承認・予算・タイムアウトの Runtime）、#87（`fmt` の折り返し、任意）。M4 からの持ち越しは、`list` を経由する再帰レコード・`weak`・`Unknown` のコンテナへの拡張（1つの ADR で決める。`docs/plans/m4.md` の「見送り」）、循環参照で生存数が残ったときの 102 のメッセージ、`fmt` の折り返し（#87）。Move 最適化の続きは M5 では扱わない。進捗は各タスクの PR と `docs/roadmap.md` で管理する。

## 方針

- **PoC4 を最初の 2 週間に置く。** 要件定義書 11 の「AI 安全性 PoC: 型付き出力、未許可ツール拒否、承認制御、監査、タイムアウト」を、ロードマップのリスク表「AI SDK の強制方式: Capability の付与がプロンプト依存になる → Runtime 強制だけで AC-007 を満たす」に合わせ、期限と成功・転換の基準を先に決めて試作する（T1）。PoC4 で確かめるのは、(1) コンパイラが生成するツール表と、JSON → 型付き引数の変換（glue）を通してランタイムがツールを呼べること、(2) 実プロバイダ（Anthropic Messages API）とスキーマ付き出力・ツール呼び出しの往復が、提案するプロトコルで成り立つこと、(3) `Unknown` にコンテナを足しても ARC の安全網（検証器・生存数・ASan）が効くこと。
- **AI 機能は専用構文にしない。`@tool` / `@agent` は「コンパイル時の属性」として実現する。** 関数値がない（E0213）ので、Python のように「関数を受け取って関数を返すデコレータ」は書けない。代わりに、デコレータの**構文**（`@name(args)` を `def` の前の行に書く。一般的な形）を文法に足し、M5 では `tool` と `agent` の2つだけをコンパイラが解釈する（未知の名前は E1401）。意味の実装は、型検査（属性の引数の検査、ツールの `uses` と agent の `capabilities` の突き合わせ）、IR の関数属性、バックエンドが生成する**ツール表**（名前・説明・引数の JSON Schema・宣言した Effect・承認の要否・エントリの関数ポインタ）と**トランポリン**（`@wys_tool_entry_f{}`: JSON の引数を検証して型付きの引数にし、関数を呼び、戻り値を JSON にする。`@wys_task_entry_f{}` と同じ型）、agent の本体を囲む `wys_agent_enter` / `wys_agent_exit`（lowering がすべての出口に入れる）で担う。要件定義書 4.5 の「まず型付き標準 SDK・デコレータ / アノテーションとして実装する」の「アノテーション」に当たる。関数値が入ったら、同じ構文のままライブラリのデコレータに置き換えられる形を保つ（利用者のコードは変えない）。これに必要な言語機能は、字句 `@`、`decorator` の文法、AST の `FuncDef.decorators`、`fmt`、属性の引数（リテラルと関数名の `list` だけ）の検査で、関数値・クロージャ・Effect 多相は要らない。
- **JSON は `Unknown` の拡張で受ける（ADR-0021）。** ADR-0011 の見直し条件（「`list` / `dict` と JSON を入れるとき、`Unknown` の構成要素を増やし、検証 API をスキーマ検証（AI-002）と共通化する」）に従い、`Unknown` に `list[Unknown]` と `dict[str, Unknown]` の種類を足し、`match` に `case list():` / `case dict():` を足す。再帰は組み込みの `Unknown` の内側に閉じるので、**利用者定義の再帰レコードと `weak` は M5 では入れない**（ADR-0021 で「入れない」と決める。E0504 は残す。スキーマの中で再帰が要る部分は `Unknown` のフィールド（「任意の JSON」）で逃がす）。入口は `parse_json(s: str) -> Result[Unknown, JsonError]`、検証は `validate[T](u: Unknown) -> Result[T, SchemaError]`（コンパイラが型 `T` ごとに復号の glue を生成する。失敗は経路付き: `steps[2].name: expected str, found int`）、出力は `to_json(v) -> str`。`T` に使える「スキーマ型」は `int` / `float` / `bool` / `str` / `None`、それらの Union、`list[T]`、`dict[str, T]`、スキーマ型だけを持つレコード、`Unknown`（任意の JSON）。`Result` / `Task` / `PyObject` / `PyError` / 型パラメータは E1501。同じ型から JSON Schema（draft 2020-12 の部分集合）の文字列定数も生成し、プロバイダへの「出力スキーマ」と「ツール定義」に使う。
- **呼び出しに型引数を明示できるようにする（`f[T](x)`、ADR-0021）。** `validate[Plan](u)` と `llm_generate[Plan](req)` は引数から `T` が決まらないので、呼び出しの型引数が要る。要件定義書 12 の非規範的な例（`llm.generate[ResearchResult](...)`）とも合う。利用者の Generic 関数にも使え、E0403（推論できない）の逃げ道になる。代替の「期待型からの推論」は `?` や `await` をまたぐと決まらないので採らない。
- **セキュリティは Runtime 強制。静的な検査は補助。** ランタイムが agent のコンテキスト（許可したツールの集合、付与した Capability、承認の方針、予算の残り）をスタックで持ち、LLM がツールを要求するたびに**実行の前に** (1) ツールが agent の一覧にあるか、(2) ツールの宣言した Effect が agent の Capability（静的な宣言と、環境変数 `WYS_CAPABILITIES` による配備時の縮小の積）に含まれるか、(3) 承認が要るなら承認の方針、(4) 予算を検査し、拒否したら監査イベントを残す（AC-007）。LLM の出力はスキーマ検証を通ったものしか型付きの値にならず、ツールの引数は glue が検証し、ツールの戻り値も JSON にしてから LLM に渡す（信頼しない）。Capability の名前は Effect の名前と同じ集合（`io` / `exit` / `python` / `llm`）にし、M5 で足す組み込みがない `fs` / `net` は入れない。コンパイラは「ツールの `uses` ⊆ agent の `capabilities`」を E1405 で検査する（ADR-0014 論点 11）が、これは早期発見のためで、保証はランタイムの検査が担う。防御を重ねるため、`wys_py_*` / `wys_exit` / `wys_llm_*` の入口でも現在のコンテキストの Capability を確かめる。**`python` はサンドボックスではない**（ADR-0018 論点 12）: `python` を付与した agent のツールは Python の内側で何でもできるので、`python` は既定で付与せず、ADR-0023 にその限界を明記する。プロセスの隔離は Phase 3。
- **LLM のプロバイダは 3 つに分け、CI は決してネットワークに出ない。** (a) **ランタイム内のモック**（既定。`WYS_LLM_PROVIDER` が未設定のとき）: プログラムが `llm_mock_push(...)` で応答（本文、ツール呼び出し、使用量、遅延）を積み、`llm_generate` が順に消費する。空なら `Err(kind="mock_exhausted")`。Conformance はこれで AC-006〜008 を決定的に検査する。(b) **実プロバイダは別プロセス** `wys llm-proxy`（`wys_cli` の副コマンド。`WYS_LLM_PROVIDER=anthropic`）: ランタイムが `std::process::Command` で起動し、stdin / stdout の JSON 行（要求: `model` / `system` / `messages` / `tools` / `schema` / `max_tokens`、応答: `text` / `tool_calls` / `usage` / `stop` / `error`）でやり取りする。HTTPS は `wys_cli` だけが `ureq` + `rustls` で持ち、生成した実行ファイルの依存は変わらない（AC-004）。API キーは proxy の環境変数だけが読み、プログラムとランタイムは秘密情報に触れない（未決定 10）。`WYS_LLM_PROVIDER=cmd:<path>` で利用者の任意のコマンドも同じプロトコルで使える（これがプロバイダ抽象化の実体）。(c) **記録済み応答の再生**は M6（AC-009、AI-008）。代替案との比較: Python の埋め込み（`urllib.request`）は ADR-0018 の仕組みを使い回せて追加の依存がないが、LLM を使うすべてのプログラムが Python 3.14 をビルド時に要求し、呼び出し中はタスクが止まる。ランタイムに HTTP クライアントを入れる案は、TLS のために外部クレートか `libcurl` が staticlib に入り、AC-004 の「依存は OS 標準のみ」が Linux で崩れる。proxy は 2 プロセスになり `wys` の実行ファイルが実行時に要る（探す順: `WYS_LLM_PROXY` → ビルド時に埋めた `wys` の絶対パス → `PATH`）が、M5 ではこれを採る。
- **`llm_generate` は `async` の組み込みにする。** M5 の実装はブロックする（proxy の応答を待つ間ほかのタスクは進まない。ADR-0020 論点 16 の Python と同じ）が、API を `await llm_generate[T](req)` にしておけば、M6 でスケジューラが proxy のパイプを待てるようにしても利用者のコードは変わらない。ADR-0020 論点 6 により、`@agent` の関数は `async def` になり、`main` も `async def main` になる。
- **タイムアウトと予算は呼び出しの境界で判定する。タスクのキャンセルは M5 では入れない。** `@agent(timeout_ms=..)` の期限は、LLM 呼び出しとツール呼び出しの前後で確かめ、超えていれば `Err(kind="timeout")` を返す。HTTP の待ち時間は proxy 側のソケットのタイムアウトで切る。ADR-0020 論点 15 の「中断点での協調的な巻き戻し」は予約のままにし、`with_timeout` とタスクグループは M6 へ送る。時計は実時間（単調時計）、`WYS_VIRTUAL_TIME=1` では仮想時計（モックの応答の `latency_ms` が仮想時計を進める）にし、タイムアウトの Conformance を決定的にする。予算は `max_llm_calls` / `max_tool_calls` / `max_tokens`（プロバイダの `usage` の合計）/ `timeout_ms` の 4 つ。費用（`max_cost_usd`）は価格表が要るので M6（価格表は proxy の adapter に置く）。
- **監査は最小にし、トレースは M6。** ランタイムが監査イベント（`tool_called` / `tool_denied` / `approval_requested` / `approval_granted` / `approval_denied` / `budget_exceeded` / `llm_called` / `schema_rejected`）を順序付きで持ち、`audit_events() -> list[AuditEvent]`（`{seq: int, kind: str, agent: str, tool: str | None, detail: str}`。時刻は含めない）で読め、`WYS_AUDIT=<path>|stderr` で JSON 行にも出す。プロンプトと応答の本文は監査に含めない（長さだけ）。全体のトレース（スパン、使用量の集計）は AI-007 として M6。
- **正しさの検査は M3 / M4 と同じ 3 つ**（IR の検証器、終了時の生存数、AddressSanitizer）を `tests/conformance/ai/` にも適用する。`validate[T]` が途中で失敗したときに作りかけの値をすべて release すること、proxy の子プロセスを ASan モードで起動できることを確かめる。性能は `validate` の処理時間と proxy の往復時間の絶対値だけを記録する（倍率は書かない）。
- **持ち越しは早めに片付ける。** T0（102 のメッセージ、E0504 のメッセージ、任意の #87）と T4 / T5（ADR-0021 の承認後）は PoC4 と並行して進める。

### PoC4 の判定（T1）

期限は 10 営業日（2026-11-19）。**成功**の基準（すべて満たす）:

1. 手書きの LLM IR とランタイムの試作で、`@tool` 2 つと agent 1 つの相当物がランタイム内モックに対して動く: モックが一覧にあるツール A を要求 → JSON の引数（`int` / `str` / レコード）を型付きに変換して実行し、戻り値を JSON で返す。モックが一覧にないツール B を要求 → 実行の前に拒否し、監査イベントが残る（AC-007 の先行確認）。`max_tool_calls=1` の後にもう一度 A を要求 → `Err(budget)`（AC-008 の先行確認）。
2. モックがレコードに合わない JSON を返す → 経路付きの `Err(schema)`。合う JSON → 型付きの値を `print` できる（AC-006 の先行確認）。途中で失敗したときも生存数 0 で、3 つのモード（Debug / Release / ASan）を通る。
3. `Unknown` に `list` / `dict` を足した試作で、深さ 3 の JSON を `match` で絞り込んで読み、3 つのモードで生存数 0。
4. `wys llm-proxy` の試作が、Anthropic Messages API に JSON Schema 付きの要求とツール定義 1 つを送り、`tool_use` → `tool_result` → 最終の JSON の往復を 1 回完了する（ユーザーのキーで手元だけ。CI では動かさない）。往復の時間を絶対値で記録する。
5. `docs/poc/poc4-results.md` に、5 フィールドのレコード 1 つあたりの glue の行数、1 MB の JSON の `parse_json` + `validate` の時間、proxy の往復の時間、ASan モードで子プロセスを起動したときの挙動を記録した。

**転換**の基準: 10 営業日で 1〜3 のどれかが macOS arm64 で動かない。次の順で範囲を狭める。

- (a) 4 だけ動かない（プロトコルかツール呼び出しの往復が成り立たない） → M5 の実プロバイダは `cmd:` の利用者コマンドだけにし、Anthropic の adapter は M6 へ。AI-001 はモックと `cmd:` で判定する。
- (b) 1 のツール表・トランポリンが重い → `@agent` を属性ではなく明示の組み込み `agent_begin(cfg)` / `agent_end()` に置き換える（ランタイムは同じ）。それでも重ければ、ツールの引数を `Unknown` 1 つ・戻り値を `str` に限り（ツールの作者が `validate[T]` で検証する）、glue はスキーマの生成だけにする。
- (c) 3 で ARC の不変条件が崩れる → `Unknown` の拡張をやめ、`PyObject` と同じ名目的なハンドル型 `Json`（`get(key)` / `index(i)` / `to_int()` などが `Result` を返す）にし、`validate[T](j: Json)` にする。ADR-0021 を書き直す。
- (d) 1 または 2 が期限内に動かない → ただちに M5a / M5b に分け（下の「分割の判断基準」）、M5a は JSON・スキーマ検証・型付き LLM API（AC-006）に集中する。

## 診断コードの帯

E14xx デコレータと `@tool` / `@agent`（E1401 未知のデコレータ名（M5 は `tool` / `agent` だけ。ヒントで一覧）、E1402 デコレータの引数の誤り（未知のキーワード、位置引数、リテラルでも関数名の `list` でもない値、型の不一致、重複）、E1403 `@tool` / `@agent` の関数に `uses` がない、`main` / `test_*` に付けている、または両方を同じ関数に付けている、E1404 `@agent` の `tools` の要素が `@tool` の関数でない、E1405 ツールの `uses` が `@agent` の `capabilities` に含まれない（足りない名前を列挙し、`capabilities` に足す修正とツールの定義を `related` に示す））。E15xx JSON とスキーマ（E1501 スキーマ型でない型（`Result` / `Task` / `PyObject` / `PyError` / 型パラメータ / キーが `str` でない `dict`）を `validate` / `llm_generate` / `to_json` の型引数か `@tool` の引数・戻り値に使っている、E1502 Generic でない関数・組み込みに型引数を書いている）。型引数の個数は E0402、`validate` / `llm_generate` に型引数がない場合は E0403（ヒントで `validate[T](...)` を示す）を流用する。Effect の `llm` は E1101 の一覧に加わるだけ。`case list():` / `case dict():` は既存の E0305 / E0602 の規則のまま。警告は足さない。

実行時: LLM・ツール・承認・予算の失敗はすべて `Err(LlmError)` で、パニックにしない。パニックは agent コンテキストの不整合（コンパイラの誤り）だけ（`runtime error: agent context mismatch (this is a compiler bug)`）。proxy を起動できない・応答が壊れている場合は `Err(kind="provider")`。`to_json` の NaN / 無限大は実行時エラー（101）。`WYS_LLM_PROVIDER` 未設定はモック、`WYS_APPROVAL` 未設定は `deny`、`WYS_CAPABILITIES` 未設定は縮小なし。

## 分割の判断基準

**M5a = T0〜T8 + T11（JSON・スキーマ検証・型付き LLM API・実プロバイダ）**、**M5b = T9〜T10（ツール表・agent コンテキスト・承認・予算）**。M5a だけで AI-001 / AI-002 と AC-006 を満たせるので、次のいずれかに当たったら **M5a で出口判定し、M5b は M6 の前の独立したマイルストーンにする**。

## 範囲外と持ち越し候補

| 項目 | 行き先 | 理由 |
|---|---|---|
| トレース（AI-007）、記録済み応答の再生と評価ケース（AI-008、AC-009） | M6 | ロードマップのとおり。M5 の監査イベントと proxy のプロトコルがその土台になる |
| Effect の推論、未使用の Effect の警告 | M6 | ADR-0014 論点 12 |
| 関数値と「本物の」デコレータ、利用者定義のデコレータ | 関数値と一緒に（M6 以降） | E0213。M5 の属性は同じ構文で置き換えられる |
| タスクのキャンセル、`with_timeout`、タスクグループ | M6 | ADR-0020 論点 15 の予約のまま。M5 のタイムアウトは呼び出しの境界で判定する |
| 非ブロッキングの LLM 呼び出し（スケジューラがパイプを待つ） | M6 / Phase 3 | `llm_generate` は `async` の API にしてあるので、利用者のコードは変わらない |
| 利用者定義の再帰レコード、`weak` | ADR-0021 で「入れない」と決める。需要が出たら Phase 3 の循環回収器の評価と一緒に | 再帰は `Unknown` に閉じる。循環参照を作れるようにすると生存数 0 の基準が崩れる |
| `fs` / `net` の組み込みと対応する Capability | 組み込みを入れるとき | M5 には対象の操作がない。Capability の名前は Effect の名前と同じにしてあるので足すだけ |
| 費用の上限（`max_cost_usd`）と価格表 | M6 | 価格表は古くなるので proxy の adapter に置き、ランタイムは `usage` だけを数える |
| ストリーミングの応答、複数のプロバイダの adapter（OpenAI など） | M6 以降 | `cmd:` で利用者が書ける。adapter は proxy に足す |
| 複数エージェントの連携、分散、チェックポイント（AI-010） | Phase 3 | Could |
| Python の隔離（サブプロセス、サンドボックス） | Phase 3 | ADR-0018 論点 12。M5 は `python` を既定で付与しないことで扱う |
| Move 最適化の続き | M6 以降 | 正しさに関係しない（`docs/plans/m4.md`） |
| DX-005（PoC5 の計測） | ユーザーの実行待ち | M2 から持ち越し |
| `fmt` の長い行の折り返し（#87） | T0 で任意。残れば M6 | 出口条件に含めない |
