# M2 実行計画（承認済み: 2026-11-04）

Fable（計画）が作成し、ユーザーが承認した。進捗は各タスクの PR と `docs/roadmap.md` の進捗表で管理する。

## 方針

- **M2 はヒープを使わない。** Union はスタック上のタグ付き値、レコードは不変の値型（受け渡し時にコピー）、`str` はリテラルとコマンドライン引数だけ（不死）、`list` は M3 のまま。
- ARC の前倒しや、解放しない暫定アロケータは入れない。ADR-0005 で、レコードは「不変・変換地点でコピー」と定めているので、M3 で参照型と ARC に切り替えても観測できる挙動は変わらない。この暫定表現は ADR-0009 に記録する。
- 制約: 再帰レコードは拒否する。ランタイムの C ABI には Union やレコードを渡さない（スカラー、ptr/len、出力ポインタのみ）。
- `match` / `case` は予約語にする（Python のソフトキーワードにはしない。ユーザー決定）。
- Generics の実用例は、`unwrap_or[T](x: T | None, default: T) -> T` や `type Pair[A, B] = {...}` で確かめる。`list[T]` は型名だけ予約し、専用の診断を出す。

## 新しい ADR

| 番号 | 論点 | 決める時期 |
|---|---|---|
| ADR-0009 | M2 の暫定値表現（ヒープなし、タグ付き Union、値型レコード、再帰レコード禁止、ランタイム ABI はスカラーのみ） | T1b 着手前 |
| ADR-0010 | モジュールと可視性（ファイル = モジュール、`pub`、import 構文、循環禁止） | T3〜T4 の間に起草、T6 前に Accepted |
| ADR-0011 | `Unknown` の実行時表現と検証 API、`case _` 必須の規則 | T5 前 |

## 新しい診断コードの帯

E03xx 絞り込み・match、E04xx Generics、E05xx レコード、E06xx Unknown、E07xx モジュール、W03xx 警告。

## 分割の判断基準

- **T4 完了時点で5週（予算の6割）を超えた**、または T6 着手時点で7週を超えた場合、M2a（T0〜T5: AC-002/003, LANG-003/004/006）で出口判定し、T6〜T9 を M2b に繰り越す。
