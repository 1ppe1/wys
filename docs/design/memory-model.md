# メモリモデル設計（PoC2 草案）

- **状態:** 草案（ADR-0005 の材料。ADR が Accepted になるまで規範ではない）
- **関連要件:** MEM-001〜006, NFR-001, AC-002, 未決定事項 4
- **前提:** ADR-0002（Rust）、ADR-0004（LLVM IR テキスト）、ADR-0008（Rust staticlib ランタイム）
- **改訂:** 2026-11-04 設計レビュー（Fable）の指摘を反映（借用の安全条件、コンテナと定数の所有権、保証範囲）

## 1. 目標と非目標

| 目標 | 要件 |
|---|---|
| 通常のコードで明示的な解放を書かない | MEM-001 |
| 所有権・参照・寿命の一貫した内部モデルをコンパイラが持つ | MEM-002 |
| 安全なコードで use-after-free と二重解放が起きない（2.2 の規則を前提とする） | MEM-005 |
| 実行時コストが予測でき、ベンチで測れる | P-07, NFR-002 |

非目標（要件定義書 4.2 の制約に従う）:
- 「GCなし・完全自動・所有権チェックなし・任意の並列処理が安全」を同時に約束しない。
- MVP（Phase 1）では循環参照の自動回収をしない。

## 2. 提案するモデル（推奨案）

### 2.1 値の分類

| 分類 | 型 | 代入・引数渡しの意味 | 解放 |
|---|---|---|---|
| 値型 | `int`, `bool`, 将来の `float` | コピー | 不要 |
| 参照型 | `str`、`list`、`dict`、`class` のインスタンス、構造的レコード（2.6） | 参照の共有（参照カウント） | 参照カウントが 0 になったとき |

文字列リテラルも参照型の `str` として扱い、2.4 の「不死（immortal）オブジェクト」として静的領域に置く。これにより、`str` の値はリテラル由来か動的に作られたかを区別せず、同じ規則で retain / release できる。

### 2.2 所有権の規則（ARC）

コンパイラが IR に `retain` / `release` を挿入する。プログラマは書かない。

| 場所・操作 | 規則 |
|---|---|
| ローカル変数のスロット | スロットは値を **+1 で所有**する。関数の入口で null に初期化する |
| スロットへの store | 新しい値を +1 で受け取り、**古い値を release** する |
| 関数の終了（すべての経路） | 参照型のスロットをすべて release する。未代入のスロットは null のまま（release は null を無視する） |
| コンテナの要素・オブジェクトのフィールド | 要素・フィールドは値を **+1 で所有**する |
| 戻り値 | **+1（所有）** で返す |
| 引数（既定） | **+0（借用）**。呼ばれた側は、値を保存するときだけ retain する |
| **借用の安全条件** | +0 で渡してよいのは、**ローカル変数のスロットから load した値**と、その呼び出しの間だけ生きる一時値に限る。**可変な場所**（コンテナの要素、`dict` の値、オブジェクトのフィールド、将来のグローバル変数やクロージャが捕捉した変数）から load した値を引数にするときは、呼び出し側が retain して +1 を保持し、呼び出しの後に release する |

借用の安全条件がないと、`f(xs[0], xs)` で呼ばれた側が `xs.clear()` を実行したとき、`xs[0]` の唯一の所有者が消えて use-after-free になる。ローカルのスロットは呼ばれた側から到達できないので、+0 で安全に渡せる（Swift の規約と同じ考え方）。

`await` やコールバックでも、同じ経路で借用が壊れる可能性がある。Phase 2 で `async` を導入する前に、この規則を再確認する（M4）。

### 2.3 Move 最適化

- 引数は +0 なので、引数渡しには元々 retain がない。Move 最適化が効くのは、値を **+1 で消費する場所**（`return`、コンテナへの追加、フィールドへの store、別のスロットへの store）に限られる。
- IR に「+1 で消費するオペランド」を定義する。ローカル変数の最後の使用がそのオペランドなら、retain と、後で行うスロットの release を省き、所有権をそのまま移す。
- 「最後の使用」は、IR 上で「同じスロットに次の store があるまで、そのスロットの load がない」ことで判定する。`while` ループでも、ループの先頭に戻る経路を含めてこの条件を調べれば足りる。
- 参照カウントが 1 のときは、`s = s + "x"` のような連結をその場で行える（コピーを省く）。
- **実装（M4 T3）:** 第1段として、局所的に判定できる2つの組を取り除く（`wys_ir::arc::optimize`、`docs/design/ir.md`）。(1) 関数の中で代入しない引数の、入口の retain と出口の release（呼び出し側が渡した値を呼び出しの間生かしておくという、2.2 の借用の安全条件に頼る）。(2) 可変な場所から読んだ値の保持のうち、最後の使用までに場所を変え得る命令がないもの。第2段（ローカルの最後の使用での所有権の移動、lowering が作る隠しスロットの複製の省略）は続くタスクで行う。安全網は変わらない（検証器、終了時の生存数、AddressSanitizer）。

- **Python のハンドル（M4、ADR-0018）:** `PyObject` はヒープオブジェクトで、最後の release で `Py_DecRef` する。いまの lowering は、Python の操作の結果をいったん隠しローカルに置くので、ハンドルは（本言語の変数が使われなくなっても）その関数を抜けるまで生きる。呼び出し位置ごとに1つのスロットで、同じ位置を繰り返すと前の値は解放されるので、生存数は増え続けない。ファイルなどを早く閉じたい場合は、Python 側で明示的に閉じる。Move 最適化（M4 T3）で短くできる。

### 2.4 オブジェクトのヘッダ

- 参照型のオブジェクトは、先頭に参照カウントを持つヘッダを置く。
- 不死オブジェクト（文字列リテラルなど）は、ヘッダに専用の値（たとえば負のカウント）を持ち、retain / release はそれを見て何もしない。
- `weak` 参照（M3）には弱参照カウントかサイドテーブルが、循環回収器の評価（Phase 3）にはトレース用のビットが要る。**ヘッダの配置は M3 で決め、それまで ABI は安定させない。**
- 解放処理（drop グルー: フィールドを順に release してからメモリを返す処理）は、ユーザー定義の型の配置を知っている**生成コード側**に置く。Rust のランタイム（ADR-0008）は、メモリの確保・返却と組み込み型だけを担当する。

### 2.5 可変性と別名

- `list` や `dict` は可変で、参照を共有する（Python と同じ意味論）。
- MVP はシングルスレッドなので、別名による可変性はデータ競合にならない。
- 並列処理（MEM-006, Phase 3）は、「共有するなら不変、可変なら所有権を移す」という型レベルの制約（Rust の `Send` / `Sync` に相当）で導入する。参照カウントは、スレッド間で共有される値に限り原子的にする。

### 2.6 循環参照

- MVP では回収しない。循環参照はメモリリークになり得ると仕様に明記する。
- 回避手段として `weak` 参照を標準ライブラリで提供する（M3）。
- Phase 3（M7 以降）で、Nim の ORC のような循環回収器を評価する。評価の基準は、ベンチで測った停止時間とスループット。

### 2.7 Union と `None` の値表現

| 型 | 表現 |
|---|---|
| `T \| None`（`T` が参照型） | ポインタ1語。`None` は null（ニッチ最適化）。retain / release は null を無視する |
| `T \| None`（`T` が値型） | タグ1バイト + 値 |
| 一般の Union | タグ + 最大の構成要素のサイズ（タグ付き共用体） |

- Union は Python と同じく**平坦化**する（`(T | None) | None` は `T | None` と同じ型）。Generics の単相化で `T = str | None` を与えたときも、同じ規則で正規化する。
- `None` の検査を型検査で強制する（AC-002）ので、null 参照のエラーは安全なコードでは起きない。

### 2.8 構造的レコードの表現

- 構造的レコード（ADR-0007）は**不変**とし、参照カウントされるオブジェクトとして持つ。
- 幅部分型（`{x, y}` を `{x}` として渡す）は、フィールドの配置が型によって違うので、**変換の地点で新しい配置のオブジェクトにコピー**する。不変なので、コピーしても意味は変わらない。
- コピーのコストが問題になる場合は、フィールドのオフセット表を渡す方式を M2 以降で検討する。
- 不変なので、根の変数を再代入しない限りフィールドの値は変わらない。これを根拠に、フィールドの経路（`p.x`）も変数と同じく絞り込める（ADR-0016）。

## 3. 保証範囲（MEM-005, NFR-001）

この表の「安全なコード」の保証は、2.2 の所有権の規則（特に借用の安全条件）をコンパイラが守ることを前提とする。

| 性質 | 安全なコード | FFI / `unsafe` 境界 |
|---|---|---|
| use-after-free | 起きない | 保証しない（境界で検証する） |
| 二重解放 | 起きない | 保証しない |
| null 参照 | 起きない（型で `None` を検査） | 境界で `Unknown` として検証する |
| メモリリーク | 循環参照がある場合は起こり得る | 保証しない |
| データ競合 | MVP はシングルスレッドなので発生しない。Phase 3 では型制約で防ぐ | 保証しない |
| 整数オーバーフロー | 実行時エラー（PoC1 で実装済み） | — |
| 境界外アクセス | 実行時エラー（`list` の添字は検査する） | 保証しない |
| スタックオーバーフロー（深い再帰） | プロセスが異常終了する。安全に回復できることは保証しない | — |
| メモリ不足 | プロセスを中止（abort）する | — |
| 反復中のコンテナ変更 | `dict`: キーの数が変わったら実行時エラー（101）。`list`: 添字で反復し、毎回長さを読み直す（Python と同じ。ADR-0015） | — |

## 4. IR への影響

- IR の型に参照型（`ref str`、`ref list[T]` など）を追加する。
- 命令に `retain` / `release` と、+1 で消費するオペランドを追加する。
- 挿入は2段階にする。lowering で 2.2 の規則どおり保守的に挿入し、別のパスで Move 最適化（冗長な組の除去）を行う。
- 現在の IR はローカルが可変スロットなので、静的に釣り合いを完全に検査するのは難しい。正しさは次の2つで確かめる。
  - デバッグビルドで、ランタイムが生存オブジェクトの数を数え、プログラムの終了時に（循環参照以外の）リークと二重解放を報告する。
  - **M3 の受け入れ条件として、Conformance テストを AddressSanitizer（`clang -fsanitize=address`）付きでも実行する。**
- 現在の「一時値はブロック内でのみ使える」規則は、生存区間解析を単純にするので維持する。

## 5. 代替案（ADR-0005 で比較する）

| 案 | 概要 | 主な利点 | 主な欠点 |
|---|---|---|---|
| **A: ARC + Move（推奨）** | 上記 | 実行時コストが予測しやすい。GC の停止がない | 循環参照。retain / release の挿入と最適化の実装が要る |
| B: トレーシング GC | ランタイムに mark & sweep などの GC を置く | 循環参照も回収できる。実装が単純 | 停止時間がある。FFI でオブジェクトの移動や固定の扱いが要る |
| C: Rust 型の所有権・借用検査 | コンパイル時に借用を検査する | 実行時コストが最小 | 学習コストが高い。Python 風の簡潔さ（P-01）と衝突する |
| D: 案A に加え、高性能部分だけ明示的な借用・Move を書ける | MEM-004 | ホットパスを最適化できる | 仕様が二層になる。Phase 3 で検討する |

## 6. PoC2 の残作業（実装で確かめること）

1. `str` の連結を導入して、2.2 の規則どおりの retain / release 挿入を最小実装する（M3 の前倒し検証）。
2. ループ内での Move 最適化が、典型的な例（文字列の組み立て、リストへの追加）で冗長な retain / release を消せるか。
3. AddressSanitizer 付きの e2e テストを CI で動かす。
4. 生成コードのサイズと実行時間を計測する（`benches/measure.sh`）。

## 7. 未決定の論点

- 小さな不変レコードを、参照型ではなく値型（コピー）として扱うサイズの閾値。
- `list[int]` の要素をボックス化しない表現（数値バッファの FFI ゼロコピー、INTEROP-003 と関係する）。
- デストラクタ（`__del__` 相当）を提供するか。提供すると解放順序が意味論に入る。
- ヘッダの配置と ABI の安定化の時期（M3）。
