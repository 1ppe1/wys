# メモリモデル設計（PoC2 草案）

- **状態:** 草案（ADR-0005 の材料。ADR が Accepted になるまで規範ではない）
- **関連要件:** MEM-001〜006, NFR-001, AC-002, 未決定事項 4
- **前提:** ADR-0002（Rust）、ADR-0004（LLVM IR テキスト）、ADR-0008（Rust staticlib ランタイム）

## 1. 目標と非目標

| 目標 | 要件 |
|---|---|
| 通常のコードで明示的な解放を書かない | MEM-001 |
| 所有権・参照・寿命の一貫した内部モデルをコンパイラが持つ | MEM-002 |
| 安全なコードで use-after-free と二重解放が起きない | MEM-005 |
| 実行時コストが予測でき、ベンチで測れる | P-07, NFR-002 |

非目標（要件定義書 4.2 の制約に従う）:
- 「GCなし・完全自動・所有権チェックなし・任意の並列処理が安全」を同時に約束しない。
- MVP（Phase 1）では循環参照の自動回収をしない。

## 2. 提案するモデル（推奨案）

### 2.1 値の分類

| 分類 | 型 | 代入・引数渡しの意味 | 解放 |
|---|---|---|---|
| 値型 | `int`, `bool`, 将来の `float`、小さな不変レコード | コピー | 不要 |
| 参照型 | 動的な `str`、`list`、`dict`、`class` のインスタンス | 参照の共有（参照カウント +1） | 参照カウントが 0 になったとき |
| 定数 | 文字列リテラル | 参照の共有（カウントしない） | 不要（静的領域） |

### 2.2 自動参照カウント（ARC）

- コンパイラが IR に `retain` / `release` を挿入する。プログラマは書かない。
- **Move 最適化:** ローカル変数の最後の使用では、`retain` + `release` の組を省き、所有権を移す。最後の使用は IR 上の生存区間解析で判定する。
- 関数の引数は「借用（borrowed）」を既定にする。呼び出し側が生存を保証するので、呼び出される側は `retain` しない（Swift の +0 規約と同じ）。値を保存する場合だけ `retain` する。
- 戻り値は「所有（owned, +1）」で返す。

### 2.3 可変性と別名

- `list` や `dict` は可変で、参照を共有する（Python と同じ意味論）。
- MVP はシングルスレッドなので、別名による可変性はデータ競合にならない。
- 並列処理（MEM-006, Phase 3）は、「共有するなら不変、可変なら所有権を移す」という型レベルの制約（Rust の `Send` / `Sync` に相当）で導入する。参照カウントは、スレッド間で共有される値に限り原子的にする。

### 2.4 循環参照

- MVP では回収しない。循環参照はメモリリークになり得ると仕様に明記する。
- 回避手段として `weak` 参照を標準ライブラリで提供する（M3）。
- Phase 3（M7 以降）で、Nim の ORC のような循環回収器を評価する。評価の基準は、ベンチで測った停止時間とスループット。

### 2.5 Union と `None` の値表現

| 型 | 表現 |
|---|---|
| `T \| None`（`T` が参照型） | ポインタ1語。`None` は null（ニッチ最適化） |
| `T \| None`（`T` が値型） | タグ1バイト + 値 |
| 一般の Union | タグ + 最大の構成要素のサイズ（タグ付き共用体） |

`None` の検査を型検査で強制する（AC-002）ので、null 参照のエラーは安全なコードでは起きない。

## 3. 保証範囲（MEM-005, NFR-001）

| 性質 | 安全なコード | FFI / `unsafe` 境界 |
|---|---|---|
| use-after-free | 起きない | 保証しない（境界で検証する） |
| 二重解放 | 起きない | 保証しない |
| null 参照 | 起きない（型で `None` を検査） | 境界で `Unknown` として検証する |
| メモリリーク | 循環参照がある場合は起こり得る | 保証しない |
| データ競合 | MVP はシングルスレッドなので発生しない。Phase 3 では型制約で防ぐ | 保証しない |
| 整数オーバーフロー | 実行時エラー（PoC1 で実装済み） | — |
| 境界外アクセス | 実行時エラー（`list` の添字は検査する） | 保証しない |

## 4. IR への影響

- IR の型に参照型（`ref str`、`ref list[T]` など）を追加する。
- 命令に `retain` / `release` を追加する。最初は lowering で保守的に挿入し、別のパスで Move 最適化（冗長な組の除去）を行う。
- 挿入の正しさは、IR 検証器に「各参照の retain / release の釣り合い」の検査を追加して確かめる（デバッグビルドでは、ランタイムのカウンタで実行時にも検査する）。
- 現在の「一時値はブロック内でのみ使える」規則は、生存区間解析を単純にするので維持する。

## 5. 代替案（ADR-0005 で比較する）

| 案 | 概要 | 主な利点 | 主な欠点 |
|---|---|---|---|
| **A: ARC + Move（推奨）** | 上記 | 実行時コストが予測しやすい。GC の停止がない | 循環参照。retain / release の挿入と最適化の実装が要る |
| B: トレーシング GC | ランタイムに mark & sweep などの GC を置く | 循環参照も回収できる。実装が単純 | 停止時間がある。FFI でオブジェクトの移動や固定の扱いが要る |
| C: Rust 型の所有権・借用検査 | コンパイル時に借用を検査する | 実行時コストが最小 | 学習コストが高い。Python 風の簡潔さ（P-01）と衝突する |
| D: 案A に加え、高性能部分だけ明示的な借用・Move を書ける | MEM-004 | ホットパスを最適化できる | 仕様が二層になる。Phase 3 で検討する |

## 6. PoC2 の残作業（実装で確かめること）

1. `str` の連結を導入して、ARC の retain / release 挿入を最小実装する（M3 の前倒し検証）。
2. ループ内での Move 最適化が、典型的な例（文字列の組み立て、リストへの追加）で冗長な retain / release を消せるか。
3. 生成コードのサイズと実行時間を計測する（ベンチ基盤は M3）。

## 7. 未決定の論点

- 小さな不変レコードを値型として扱うサイズの閾値。
- `list[int]` の要素をボックス化しない表現（数値バッファの FFI ゼロコピー、INTEROP-003 と関係する）。
- デストラクタ（`__del__` 相当）を提供するか。提供すると解放順序が意味論に入る。
