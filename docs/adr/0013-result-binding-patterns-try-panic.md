# ADR-0013: `Result[T, E]`、束縛パターン、`?`、パニックの仕様

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** LANG-008、NFR-007、ADR-0006、ADR-0007、ADR-0009、ADR-0011、ADR-0012、`docs/plans/m3.md` T5

## 背景

ADR-0006 では次のことを決めた。

- エラー処理には `Result[T, E]` と後置の `?` を使う。
- `?` は `Result` だけに使える。
- エラー型は、関数が宣言したエラー型に収まる場合だけ伝搬できる。
- `?.` と `??` は導入しない。
- 実行時エラーはパニックとして扱い、終了コードは 101 とする。

一方で、次のことは決めていない。

- `Result` の正体（どういう型として扱うか）
- 値の表現と ARC の関係
- 束縛パターンの文法とスコープ
- `?` の型付けの詳細
- パニックの書式（NFR-007）

いまの `match` は、Union のタグを検査して被検査値の変数を絞り込むだけで、値を束縛できない（パターンは型パターン・`None`・`_` の3種類）。

## 選択肢と決定

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 1. `Result` の正体 | 型検査では、組み込みの名目的な Generic 型として扱う（`list` と同じ登録表を使う）。`Ok` と `Err` は型ではなく構築子。IR では、構成要素が2つの Union として扱う（タグ 0 が `Ok`、タグ 1 が `Err`） | `Ok[T] \| Err[E]` という Union の糖衣にする | Union は「区別できる型の集合」で、平坦化・E0508・`Unknown` の吸収という不変条件がある。`Result` を Union にするとこれが崩れる。名目的で構築子を持つ和型は、将来の `enum`（ADR-0007）の雛形にもなる。IR では既存の Union 命令と解放処理（drop glue）をそのまま使える |
| 2. 構築子の型付け | `Ok(v)` では、`T` を `v` から、`E` を期待型から決める。`Err(e)` では、`E` を `e` から、`T` を期待型から決める。期待型は、注釈付きの代入、既存の変数への代入、`return`、Generic でない関数の引数から得る。期待型が `Result \| None` なら、その `Result` を使う。決まらなければ E1001 | 下界の型（Never）を導入する | 下界の型は型の体系を複雑にする。空のリスト `[]` が E0901 で注釈を求めるのと同じ運用にする |
| 3. 値の表現と ARC | Union と同じく、タグ付きの値型にする（ADR-0009）。参照型を含む場合の retain / release は、既存の Union 用の解放処理で行う。`case Ok(x):` の `x` は、payload を `x` のスロットに格納し、スロットが +1 で所有する | 束縛を借用のままにする | memory-model 2.2 の「スロットは +1 で所有する」に揃える。冗長な retain / release の組は、後で Move 最適化で消す |
| 4. 束縛パターン | 文法は `pattern = IDENT "(" [ IDENT \| "_" ] ")" \| "None" \| "_"`。束縛を書けるのは `Ok` / `Err` だけで、`Ok()` や `int(n)` は E1004 になる。束縛変数のスコープは `case` の本体だけ（初めてのブロックスコープの変数）。関数内の既存の変数や引数と同じ名前は E1005。別の `case` なら、同じ名前で別の型でもよい | Python のように関数スコープに漏れる。型パターンにも束縛を許す | 「最初の代入で型が決まる」規則と衝突しない。型パターンの束縛は変数の絞り込みで代わりができるので、T5 の範囲外にする（AST は一般形にしておく） |
| 5. Union の中の `Result` | `Result \| None` の被検査値は、`case Result():`（型パターン、束縛なし）で絞り込む。`Ok(x)` を書けるのは、被検査値の型がちょうど `Result` のときだけ（それ以外は E1003。ヒントで「先に `is None` で検査する」と示す）。1つの Union に入れられる `Result` は1つまで（E1002） | — | パターンの入れ子を T5 に持ち込まない |
| 6. 網羅性 | `Result` は `Ok` と `Err` の2つに分けて数える。足りないときの E0303 のヒントは `case Ok(x):` / `case Err(e):`。到達しない `case` は従来どおり W0301 | — | 既存の集合差による検査を流用できる |
| 7. `?` | 後置の演算子（`-f()?` は `-(f()?)`）。直後に `.` や `[` が続くと E0101 にする（括弧で囲む）。これで ADR-0006 の「`?.` を導入しない」を守る。被演算子が `Result` でなければ E1010。囲む関数の戻り値が `Result` でなければ E1011（`main` や `test_*` も含む）。被演算子の `E` の構成要素がすべて、宣言されたエラー型に収まらなければ E1012（収まらない構成要素を列挙する）。`f()?` を式文として書いてもよい。Generics では型パラメータどうしを同一性で照合する | `T \| None` にも `?` を使えるようにする | ADR-0006 で却下済み |
| 8. `main` の戻り値 | `main -> Result[None, E]` は T5 では認めない（E0210 のまま） | 認めて、`Err` で終了コード 1 にする | 見直し条件は、AI が生成するスクリプトで需要があること |
| 9. 型引数の制約 | `E` には任意の型を使える。ただし `None` 単独と `Unknown` は不可（E1002）。`T` には `None` を含め任意の型を使える（`Result[None, str]`）。`Result[Unknown, str]` は `list[Unknown]` と同じに扱う | `E` を `str` に限る | `E1 \| E2` への伝搬という規則の価値がなくなる |
| 10. パニックの書式 | stderr に `runtime error: <message>` と出す（いまの接頭辞を正式な仕様にする。機械的にはこの接頭辞で判別する）。場所が分かるものは ` at file:line:col` を付ける。終了コード 101 を正式な仕様にする。stdout を flush してから出す。スタックトレースは出さない | 接頭辞を `panic:` に変える | 既存の Conformance と e2e を壊さない。スタックトレースは、デバッグ情報を入れるときに見直す |
| 11. パニックと検査 | パニックや `exit()` では `wys_runtime_finish` を呼ばない。そのため、生存オブジェクト数の検査（終了コード 102）は正常終了したときだけ働くと明記する | — | 異常終了の経路で生存数を数えても意味がない |
| 12. `panic(msg: str)` | 組み込み関数として追加する。`exit` と同じく、戻らない文として扱う。書式は `runtime error: <msg> at file:line:col` | 入れない | 想定外の状態を明示して止められるようにする。`unwrap` の代わりになる |
| 13. `unwrap` / `expect` | 入れない。失敗を握りつぶす箇所は `case Err(e): panic(...)` と書いて、目立たせる | 入れる | AI が生成するコードが `unwrap` を濫用するのを防ぐ（NFR-007）。`Result` にはまだメソッドがない。見直し条件は `enum` にメソッドを入れること |
| 14. その他の演算 | `print(r)` は E0201、`r == s` は E0207、`r is None` は E0302 にする（いずれも既存の規則のまま） | — | — |
| 15. Generics との関係 | E0401（型パラメータに対する型パターン）はそのまま。`Result[T, E]` に対する `case Ok(x):` は許す。検査するのは `Result` のタグで、`T` ではないから。被検査値が素の `T` なら E1003 | — | 単相化の前に網羅性検査が完結する性質（ADR-0006）を保つ |

`Ok`、`Err`、`Result`、`panic` は予約語ではなく組み込みの名前にする。再定義すると E0209 になる。

## 新しいエラーコード（E10xx 帯）

| コード | 内容 |
|---|---|
| E1001 | `Ok` / `Err` の、もう一方の型が期待型から決まらない |
| E1002 | `Result` の型引数の制約に違反している（`E` が `None` や `Unknown`、または1つの Union に `Result` が2つある） |
| E1003 | `Ok(x)` / `Err(e)` を、`Result` ではない被検査値（Union や型パラメータ）に使っている |
| E1004 | 束縛の個数や対象が正しくない（`Ok()`、`int(n)`） |
| E1005 | 束縛変数の名前が、既存の変数や引数と同じ |
| E1010 | `?` を `Result` 以外に使っている |
| E1011 | `Result` を返さない関数（`main` を含む）で `?` を使っている |
| E1012 | 被演算子のエラー型が、宣言されたエラー型に収まらない |

## 影響

- 実装を3つに分ける。
  - **T5a:** `Result` の型、構築子、束縛パターン
  - **T5b:** `?`
  - **T5c:** パニックの仕様と `panic()`
- 更新する文書:
  - `grammar.ebnf`（パターン、後置の `?`）
  - `error-codes.md`（E10xx、実行時エラーの表に `panic`）
  - `ir.md`（`Result` は構成要素が2つの Union）
  - 用語集（パニック、束縛パターン）
  - ADR 一覧
- ASan モードでは、終了時の生存数検査（102）をリークの基準にしている。そのため、Linux の LeakSanitizer は harness で無効にする（`ASAN_OPTIONS=detect_leaks=0`）。
- 見直し条件:
  - `enum` を導入するとき、`Result` を一般の名目的な和型に統合する。
  - `main` が `Result` を返すことへの需要が出たら、8 を見直す。
