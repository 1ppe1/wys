# ADR-0010: モジュールと可視性

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** 未決定事項 1（ファイル単位の可視性規則）、LANG-001、DX-002、INTEROP-004、`docs/plans/m2.md` T6

## 背景

M2 の T6 で、複数ファイルからなるプログラムを扱えるようにする。次の4点を決める必要がある。
1. モジュールの単位と、名前の解決方法
2. import の構文
3. 公開・非公開の決め方（可視性）
4. 循環 import の扱い

言語名、拡張子、パッケージ名（未決定事項1の残り）と、パッケージ管理（INTEROP-004）は、この ADR では扱わない。

## 選択肢と推奨

| 項目 | 推奨 | 主な代替案 | 推奨の理由 |
|---|---|---|---|
| モジュールの単位 | **1ファイル = 1モジュール**。名前はエントリファイルのディレクトリからの相対パス（`util/text.wys` → `util.text`） | ディレクトリ = モジュール | Python と同じで、AI も人間も場所を推測しやすい |
| import の構文 | `import util.text`（`util.text.f()` で参照）と `from util.text import f, g` | `use` などの独自構文 | Python と同じ。`import ... as ...` は M2 では入れず、後で追加できるようにしておく |
| 可視性 | **`pub` を付けたものだけ公開**（`pub def f`、`pub type P = ...`）。付けなければモジュール内だけで使える | Python と同じく、すべて公開（`_` で始まる名前は慣習として非公開） | 公開 API をコンパイラが機械的に判定できる（構造化診断、将来の `.d.ts` 生成やドキュメント生成）。AI が非公開の関数に依存してしまう誤りを、コンパイル時に検出できる |
| 循環 import | **禁止**（E0703）。循環の経路を診断に示す | 許可して遅延解決する | 初期化順序の問題を避ける。型検査と単相化（T4）を単純に保つ |
| `main` | エントリファイルの `main` だけをエントリポイントにする。ほかのモジュールの `main` は普通の関数 | — | — |
| 名前の衝突 | `from m import f` と同じモジュールの `f` が衝突したら E0704 | 後勝ち | 暗黙の上書きをしない |
| 生成コードの名前 | `wys_fn_<モジュールのパス>__<名前>`（`.` は `_` に置き換える） | — | モジュールが違えば同名の関数を区別できる |

## エラーコード（T6 で実装）

| コード | 内容 |
|---|---|
| E0701 | import したモジュールが見つからない |
| E0702 | 公開されていない名前を、ほかのモジュールから使っている（修正ヒント: 定義に `pub` を付ける） |
| E0703 | 循環 import（経路を示す） |
| E0704 | import した名前と、モジュール内の定義が衝突している |

## 決定

上表の「推奨」の列を採用する（可視性は `pub` 方式。ユーザー決定）。

## 影響

- **Python との違い:** `pub` を書く必要がある。言語仕様と、Python 利用者向けの説明で明示する。
- **既存のコードへの影響:** 1ファイルのプログラム（今の Conformance ケースや例）は、`pub` がなくてもそのまま動く。可視性が問題になるのは、ほかのモジュールから使う場合だけ。
- **ツール:** 診断の位置にファイル名を含める仕組みは、すでにある。複数ファイルの Conformance ケースのために、ディレクトリ型のケース（`tests/conformance/modules/<名前>/main.wys`）を追加する。
- **見直し条件:** パッケージ管理（INTEROP-004）を設計するときに、モジュールのパスの起点（エントリファイルのディレクトリ）を、プロジェクトのルートに変えるかを再検討する。
