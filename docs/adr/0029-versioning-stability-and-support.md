# ADR-0029: 版の付け方・安定性の段階・互換性の範囲・サポート期間

- **状態:** Proposed
- **日付:** 2026-11-11
- **関連:** NFR-006、NFR-007、NFR-008、未決定事項 12（サポート期間。性能 SLO は未決のまま）、ADR-0003（対象環境）、ADR-0018（Python 3.14）、`docs/plans/release.md` T4 / T15、#73

## 背景

NFR-008 は「言語仕様・標準ライブラリ・ABI のバージョニング方針と破壊的変更ルールを持つ」ことを求める。いまは `version = "0.0.0"` で、タグはない。公開する面ごとに、変わり得る度合いが違う: 構文と標準関数はまだ動くが、診断のコードと JSON の形は M1 から `schema_version` で管理し、コードを再利用しない規則がある。proxy の JSON 行のプロトコル、記録、トレースも `v` を持つ。

未決定事項 12 のうち、性能 SLO はベンチと利用者の検証の後に決める（要件定義書）。サポート期間は公開前に決める必要がある。

## 選択肢

### 案A: 0.x は「何でも変わり得る」とだけ書く

- 利点: 約束が最小。
- 欠点: 既に安定させている面（診断の JSON、エラーコード）の約束が伝わらない。NFR-008 の「規則」としては弱い。

### 案B: SemVer 0.y.z と安定性の段階表

- 利点: 面ごとの約束が明確。既存の規則（`schema_version`、エラーコードの不変）をそのまま位置付けられる。
- 欠点: 表を保守する必要がある。

### 案C: 日付の版（2026.11 など）

- 利点: 版の意味で迷わない。
- 欠点: 破壊的変更の有無が版から分からない。Rust / cargo の慣例と合わない。

## 決定

**案B を採る。**

1. **版**: SemVer の `0.y.z`。最初のタグは `v0.1.0`。`0.y` の間は、`y` を上げるときに破壊的変更を入れてよい。`z` は破壊的変更を含まない修正だけ。`1.0` の条件は別に決める（この ADR では決めない）。
2. **安定性の段階**:

| 面 | 段階 | 約束 |
|---|---|---|
| 言語の構文と意味、組み込みの関数と型 | 不安定 | `0.y` を上げるときに変わり得る。CHANGELOG に列挙する |
| エラーコード | 安定 | 意味を変えず、再利用しない。廃止は「廃止」と明記して残す（既存の規則） |
| 診断の JSON（`check --format json`）、`wys explain` の JSON | 版で管理 | `schema_version` を上げずに項目を消したり意味を変えたりしない。項目の追加は版を上げない |
| proxy の JSON 行のプロトコル、記録（`WYS_LLM_RECORD`）、トレース（`WYS_TRACE`） | 版で管理 | `v` で管理する（ADR-0023 / ADR-0025） |
| CLI の副コマンドとフラグ、環境変数 | 不安定（文書化する） | `0.y` を上げるときに変わり得る |
| ランタイムの ABI、IR、クレートの API、内部名（ADR-0027） | 内部 | 約束しない |

3. **対象環境**（NFR-006）: Tier 1 = macOS arm64（手元の CI ですべてのモードを回す）。Tier 2 = Linux x86_64（版ごとに Docker で CI を回す）。Windows は非対応。Python は 3.14 だけ（ADR-0018）。「Python との完全互換ではない」と明記する。
4. **サポート期間**: 最新の `0.y` だけ。修正は最新の `0.y.z` に出す。古い `0.y` への修正の持ち帰りはしない。
5. **性能 SLO**: 未決のまま（ベンチの公開 `docs/benchmarks.md` と利用者の検証の後）。
6. **CHANGELOG**: Keep a Changelog の形式。`0.1.0` には M0〜M6 の要約を書く。
7. **NFR-007 の挙動**（パニック、`Result`、FFI の失敗、ツールのタイムアウト）は、ADR-0013 / ADR-0018 / ADR-0023 の決定を `docs/stability.md` に集約して公開する。この ADR では新しい挙動を決めない。

## 影響

- T14 で `Cargo.toml` の `version = "0.1.0"`、`CHANGELOG.md`。T15 で `docs/stability.md`（段階表、Tier、Python 3.14、NFR-007 の挙動、内部とみなすもの）。T6 の `--version` が版を出す。
- 承認したら、ADR 一覧の未決定事項 12 の欄を「サポート期間のみ」として更新する。
- 見直し条件: `1.0` を検討するとき、外部の利用者から長期サポートの要望が出たとき、Tier 2 を CI で継続的に回せるようになったとき。
