# ADR-0009: M2 の暫定値表現（ヒープを使わない）

- **状態:** Superseded by [ADR-0012](0012-heap-objects-and-arc-pass.md)（`str` / `list` / `dict` はヒープ上の参照型になった。レコードと Union を値型にする決定は、ADR-0012 と M3 計画が引き継いでいる）
- **日付:** 2026-11-04
- **関連:** ADR-0005（メモリモデル）、ADR-0006、ADR-0007、`docs/design/memory-model.md` 2.7・2.8、`docs/plans/m2.md`

## 背景

M2 では Union（`T | None` を含む）、レコード、`Unknown` を実装する。ADR-0005 のメモリモデル（ARC）の実装は M3 の予定で、M2 の時点ではヒープ上の値を安全に解放する仕組みがない。
M2 の機能を、ARC を前倒しせずに実装する方法を決める必要がある。

## 選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A: 暫定アロケータ（解放しない） | ヒープに確保し、解放はしない | オブジェクトのヘッダ配置（事実上の ABI）を M2 で決めることになる。ADR-0005 は「ヘッダは M3 で決める」としている。M3 の AddressSanitizer の受け入れで、リーク前提のケースを書き直すことにもなる |
| B: ARC の最小実装を前倒し | `str` などに retain / release を入れる | M3 のリスクを M2 に持ち込み、型の拡張とメモリの実装が同時に進む |
| **C: 値型だけで表現する（推奨）** | ヒープを使わない | ADR-0005 のレコードの意味論（不変、変換地点でコピー）と矛盾しない |

## 決定

案Cを採用する。M2 の値は次のように表す。

| 値 | 表現 |
|---|---|
| Union（`T \| None` を含む） | スタック上のタグ付き値（タグ + 最大の構成要素の大きさ）。LLVM では `{ i8, [W x i64] }` |
| レコード | 不変の値型（LLVM の構造体）。受け渡しはコピー。幅部分型は変換地点で新しい配置にコピーする |
| `str` | 不死の文字列（リテラルとコマンドライン引数）。ptr と長さの組 |
| `Unknown` | `int` / `bool` / `str` / `None` のタグ付き値 |
| `list` | M3 まで提供しない（型名だけ予約する） |

制約:
- 再帰的なレコード（`type Node = {next: Node | None}`）は M2 では拒否する（E0504）。
- ランタイムの C ABI には Union やレコードを渡さない。スカラー、ptr と長さ、出力ポインタだけを使う（OS による構造体渡しの ABI の違いを避けるため）。

## 影響

- これは **ADR-0005 を置き換えない暫定表現**である。M3 で参照型と ARC を導入するとき、レコードは参照カウントされる不変オブジェクトに、`str` は ADR-0005 の参照型に移る。
- レコードは不変なので、表現を値型から参照型に変えても、プログラムから見える挙動は変わらない（変わるのは `dump-ir` と LLVM の出力だけ）。この性質を Conformance テストで保つ。
- 大きなレコードのコピーのコストは、M3 で値型と参照型を分ける閾値（`memory-model.md` 7章）と合わせて決める。
