# ADR-0015: `dict[K, V]` のキー、反復の順序、反復中の変更

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** ADR-0006、ADR-0012、ADR-0013、`docs/design/memory-model.md` 2.2・3章、AC-002、`docs/plans/m3.md` T6

## 背景

`list[T]` を支える仕組みは、T4b までにそろった。

- 値はポインタ1語で表す。ヘッダは `{rc, len}` と互換にする。
- 要素は箱に入れず、要素の大きさ付きのバッファに置く。
- 解放処理（drop glue）は生成コードが持つ。
- `xs[i]` の結果はすぐ retain する（借用の安全条件）。

`dict` では、新たに次のことを決める必要がある。

- キーの制約（ハッシュと等価をどこで実装するか）
- 反復の順序
- 反復中に変更したときの扱い
- `d[k]` でキーがないときの扱い
- 構文（`{}` とレコード型の衝突）

## 選択肢と決定

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 1. キーの型 | `int` / `bool` / `str` だけ。Union、`None`、レコード、`list`、`dict`、`Unknown`、型パラメータは E0907 | レコードも許し、生成コードがハッシュ glue を作る | 3種類なら、ハッシュと等価をランタイム（Rust）に閉じ込められる。レコードをキーにするには、構造的な等価のハッシュと、型パラメータの制約（`Hashable` 相当）が要り、Generics の設計に踏み込むことになる |
| 2. 実装方式 | ランタイムに、CPython と同じ方式のハッシュ表を持つ。挿入順のエントリ配列と、開番地法の索引表（線形探索、負荷率 2/3）の2つで構成する。値は箱に入れず、エントリに直接置く。オブジェクトの先頭は `Header` と互換にする。キーのハッシュ（乱数化しない。整数は乗算で混ぜる）と `str` の等価はランタイムが持つ。キーと値の retain / release と drop glue は、生成コードが `dict` の型ごとに作る | ハッシュ表全体を生成コードで持つ | ADR-0012 の分担（ランタイムはメモリとバッファ、型ごとの参照カウント操作は生成コード）と同じ |
| 3. 反復の順序 | **挿入順を保証する**。既存のキーへの代入は順序を変えない | 未規定 | 出力が決定的になり、AI が生成するコードとテストが安定する。コストはエントリ配列だけ |
| 4a. `dict` の反復中の変更 | 反復中にキーの数が変わったら、**パニック**（`dict changed size during iteration`、終了コード 101）にする。既存のキーの値を変えるのはよい | 未規定 | 索引の再配置で反復の順序が壊れ得るので、検出して止める（Python と同じ） |
| 4b. `list` の反復中の変更 | 添字で反復し、毎回 `len` を読み直す。これを仕様として明記し、パニックにはしない（Python と同じ挙動）。memory-model 3章の「M3 で決める」は、この ADR で閉じる | パニックにする | Python との互換を優先する。メモリ安全は保たれる |
| 5. 構文 | リテラルは `{k: v, ...}`。空の `{}` は型注釈が必要（E0906）。レコード型の `{x: int}` は型の位置にしか現れないので、式の位置の `{` と衝突しない。比較演算に `k in d` / `k not in d` を追加する（`in` は予約語。`for x in` とは衝突しない） | `dict(...)` 構築子 | Python と同じ見た目にする |
| 6. 操作 | `d[k]`（キーがなければパニック `key not found: <key>`）、`d[k] = v`（追加または置き換え）、`k in d`、`d.get(k)`（`V \| None` を返す）、`len(d)`、`for k in d:`。削除（`d.pop(k)`）は T6b で入れる。`del` 文、`.keys()` / `.values()` / `.items()`（タプルが要る）、`x in list`、`.get(k, default)` は入れない | `d[k]` が `V \| None` を返す | `d[k]` が Optional だと、`d[k] + 1` が毎回 E0301 になって書きにくい。キーがないかもしれないことは、`.get` と `in` で明示する |
| 7. `.get` と `None` | 値の型 `V` が `None` を含む `dict` に `.get` を使ったら E0908 | Union として平坦化する | 平坦化（ADR-0006）すると、「キーがない」と「`None` が入っている」を区別できなくなる。この場合は `in` と `d[k]` を使う |
| 8. 借用の安全条件 | `d[k]` と `d.get(k)` の値、`for` のキーは、可変な場所から load した値として扱い、読んだ直後に retain する（`xs[i]` と同じ）。反復変数のスロットは +1 で所有する。`d[k] = v` はキーと値を +1 で消費し、既存のキーなら新しいキーと古い値を release する | — | memory-model 2.2 |
| 9. その他 | `print(d)` は E0201、`d == e` は E0207（`list` と同じ。T10 で一緒に見直す）。`dict[K, V]` は `K`・`V` とも不変（invariant）。`dict[str, Unknown]` は `list[Unknown]` と同じに扱う。メソッドを呼べるのは、受け手がローカル変数のときだけ（`list.append` と同じ制限） | — | — |

## 新しいエラーコード

| コード | 内容 |
|---|---|
| E0906 | 空の `{}` のキーと値の型が決まらない |
| E0907 | `dict` のキーに使えない型 |
| E0908 | 値の型が `None` を含む `dict` に `.get` を使っている |
| E0909 | `in` の右辺が `dict` ではない |

実行時エラー（パニック、101）:
- `key not found: <key>`
- `dict changed size during iteration`

## 影響

- 実装を2つに分ける。
  - **T6a:** 型、リテラル、`d[k]`、`d[k] = v`、`in`、`.get`、`len`、`for`
  - **T6b:** `.pop(k)`（墓標（tombstone）と、伸長時の圧縮）
- IR に `dict` の型と命令（作成、要素数、キーの存在、値の読み出し、書き込み、反復）を追加する。
- 更新する文書:
  - `grammar.ebnf`（`dict` のリテラル、`in`）
  - `error-codes.md`
  - `ir.md`
  - `memory-model.md` 3章（反復中の変更の行を確定する）
  - 用語集
  - ADR 一覧
- 見直し条件:
  - レコードや `enum` をキーにしたい需要が出た場合（生成コード側のハッシュ glue を検討する）
  - タプルを導入した場合（`.items()` を追加する）
  - `.get` の二重の検索（存在の確認と値の読み出し）が、計測で問題になった場合
