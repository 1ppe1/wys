# ADR-0014: Effect の基礎（Phase 1 は注釈だけ）

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** AI-009、AI-004、AI-005、DX-004、P-05、未決定事項 5、ADR-0010、ADR-0013、ADR-0017、`docs/plans/m3.md` T9、`docs/roadmap.md`（M5 Capability Runtime、M6 Effect 推論）

## 背景

要件定義書は次のことを求めている。

- ネットワークやファイル操作などを Effect として表現し、静的診断と Runtime 強制を連携させる（AI-009）。
- `explain` で Effect を説明する（DX-004）。

一方でセキュリティ原則は、外部リソースへの権限を保証するには Runtime 側の強制が必要だとしている。Effect は権限を保証するものではなく、静的に説明し検査するための道具である。

ロードマップでは、Phase 1 は注釈だけにし、型と IR に Effect の置き場所を先に確保するとした。推論は M6、Capability の Runtime 強制は M5 で扱う。ADR-0017 では、`wys explain` の Effect の項目をこの ADR の後で v0 に追加すると決めた。

いまのコンパイラには、Effect を置く場所がない。

- 関数定義の構文は `def f(...) -> T:` だけで、デコレータもない。
- 型検査の `FuncSig` にも、IR の `Function` にも、属性の欄がない。
- 外界と関わる組み込み関数は4つ。`print`（標準出力）、`arg` / `arg_count`（コマンドライン引数）、`exit`（プロセスの終了）。`panic` / `assert` と算術の実行時エラーはパニックとして扱う（ADR-0013）。
- 関数を値として使えない（E0213）ので、Effect 多相はまだ要らない。

この ADR では、Phase 1 について次の4点を決める。推論、Runtime での強制、細かい分類は M5 / M6 に残す。

- 何を Effect と呼ぶか
- どう書くか
- 何を検査するか
- どこに持つか

## 選択肢と決定

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 1. Phase 1 の Effect の種類 | `io` と `exit` の2つだけにする。`io` は外界との入出力（いまは `print` と `arg` / `arg_count`）、`exit` はプロセスの終了（いまは `exit`）。どちらも組み込みの名前で、利用者は定義できない | `io` 1つだけにする。`console` / `env` のように細かく分ける。非決定性（`ndet`）や FFI の仮置き（`ffi`）を先に入れる | 対応する組み込み関数がある種類だけにする。`exit` を分けると、AI が生成したツール関数が「プロセスを止め得る」ことを、`io` と区別して読める。増える組み込みは1つだけ。乱数・時刻・ファイル・ネットワークは Phase 1 にない。`fs` / `net` / `llm` は M5（AI SDK）、`python` / `ffi` は M4 の FFI の ADR で足す。名前を足すだけなので、既存の注釈は壊れない |
| 2. パニック | Effect にしない（Rust と同じ）。`panic` / `assert`、整数のオーバーフロー、添字の範囲外などは、どの関数でも起こり得る実行時エラーとして扱う | `panic` を Effect にする（Koka の `exn` 相当） | 算術を使うほぼすべての関数に付くので、情報にならない。回復できる失敗は、`Result` と `?` で型に現れる（ADR-0013）。パニックは処理を止めるための仕組みで、権限とは関係がない |
| 3. 構文 | 戻り値の型の後ろに `uses` 節を置く。例: `def f(x: int) -> int uses io, exit:`。Effect がないことは `uses pure` と書く。`uses` と `pure` は予約語にせず、`type` と同じくこの位置でだけ意味を持つソフトキーワードにする。文法: `func_def = "def" IDENT [ type_params ] "(" [ params ] ")" "->" type [ effects ] ":" block ; effects = "uses" IDENT { "," IDENT } ;` | (a) Koka 風の `-> int ! io`。(b) デコレータ `@effects(io)`。(c) 型の一部にする `-> int & io` | 「呼び出し先の Effect ⊆ 呼び出し元の Effect」というシグネチャの規則なので、シグネチャの位置に書く。(a) は `!=` と紛らわしく、新しい字句が要る。(b) のデコレータは M5 の SDK（`@tool` / `@agent`）のために取っておく。Effect は AI 向けの糖衣ではなく、言語の意味論の側にある。(c) は型の体系に Effect が混ざり、Union の不変条件（ADR-0006）とぶつかる。`uses` は英語として読め、`fmt` も変える必要がない |
| 4. 注釈のない関数 | 検査しない（制約もなく、推論もしない）。注釈のない関数からは何でも呼べる | (a) 注釈がなければ純粋とみなす（Koka）。(b) 注釈がなければ推論する | (a) にすると、既存のケース 138 ファイルのうち 31 ファイルが壊れる。AI が生成する Python 風のコードも大半が壊れる。Phase 1 の目的は置き場所の確保で、強制は M6 の推論と M5 の Runtime が担う。(b) は M6 で扱う |
| 5. 検査の規則 | 注釈のある関数 `f`（宣言した集合 `D`）の本体で関数 `g` を呼ぶたびに、次のように検査する。`g` が組み込み関数なら、下の表の集合 `E(g)` が `D` に含まれること。`g` に注釈があれば、`D(g)` が `D` に含まれること。含まれなければ E1102（足りない Effect を列挙し、`uses` に足す修正を示す）。`g` に注釈がなければ E1103（`g` に `uses ...` か `uses pure` を付けるよう促す）。自己再帰は常に通す。メソッド（`append` / `get` / `pop`）、演算子、`?`、`match` は Effect を持たない。検査は型検査で行うので、モジュールをまたぐ呼び出し（`a.b.f`）にも同じ規則を使う | 注釈のある関数から、注釈のない関数を呼ぶことを許す | 許すと、注釈のある関数の集合が閉じず、`uses pure` が何も保証しなくなる。E1103 があれば、「注釈は呼び出し木の葉から付ける」運用を機械的に促せる。M6 で推論が入れば E1103 は要らなくなる。制約を緩める方向の変更なので、互換性は保たれる |
| 6. 組み込み関数の Effect | `print` は `io`、`arg` / `arg_count` は `io`、`exit` は `exit`。`panic` / `assert` / `len` / `range` / `parse_scalar` / `Ok` / `Err` は Effect なし | `arg` を `env` にする | 論点 1 のとおり。`arg` は、引数が同じでも結果が変わるので純粋ではない |
| 7. `main` / `test_*` | 特別扱いしない。注釈がなければ論点 4 のとおり検査しない。書けば検査する（`def main() -> None uses io, exit:`）。E0210 / E0801 は引き続き引数と戻り値だけを見る | `main` の既定を `io, exit` にする | 既定を作ると、「注釈がなければ検査しない」の例外になる。M6 で推論が入ったときに改めて決める |
| 8. Generics とモジュール | Effect は型（`Ty`）の一部ではなく、関数の属性にする。型引数は Effect に影響しない。単相化したインスタンスは、宣言した Effect を引き継ぐ。`pub` とは関係しない。Effect の名前はモジュールに属さない | 型パラメータに Effect 変数を持たせる | 関数値がないので、Effect 多相は書けない。関数値を入れるときに見直す |
| 9. 置き場所 | AST: `FuncDef.effects`（名前の並びと、`uses` 節の範囲）。型検査: `FuncSig.effects`（注釈がなければ `None`）と、呼び出しごとの Effect の記録（`wys explain` 用）。IR: `Function.effects`。`dump-ir` では `fn f0 log(l0: str) uses io {` のように戻り値の後に出す。バックエンドは読まないので、生成コードは変わらない | IR には持たない | ロードマップの「IR に置き場所を確保する」に従う。ADR-0017 の `RcReason` と同じく、後続のパスが使える属性として運ぶ。`Ty` には入れない（論点 8） |
| 10. `wys explain` | v0 の `function` に `effects` を追加する。項目の追加なので版は上げない（ADR-0017 論点 1）。`declared` は宣言した Effect の配列で、注釈がなければ `null`。`required` は、本体の呼び出しから分かる Effect の和集合（組み込み関数と注釈のある関数の分だけ）。`sites` は呼び出しごとの `callee`・`span`・`effects`・`annotated`。識別子は英語の `io` / `exit` | `required` を推論結果と呼ぶ | 推論ではない（注釈のない呼び出し先の分は含まない）ので、`annotated: false` で区別する。M6 で推論が入ったら、`required` が推論結果になる |
| 11. Runtime | 何もしない。Effect は実行時の表現を持たない。Capability の付与・拒否・監査は M5 の Runtime で扱う（AI-004 / AI-005 / AC-007） | 注釈を Runtime の権限表に写す | セキュリティ原則（権限をプロンプトや静的な注釈に依存させない）に従う。M5 の `@tool` が宣言された Effect を読み、Capability と突き合わせる方向を想定しているが、この ADR では決めない |
| 12. 見送るもの | 推論（M6）。未使用の Effect の警告（W02xx 帯、推論と一緒に M6）。利用者定義の Effect。階層的な名前（`io.fs` など）。Effect 多相と関数値。`ffi` / `python`（M4）。`fs` / `net` / `llm`（M5）。Runtime での強制（M5） | — | Phase 1 は置き場所と注釈の検査だけにして、規模を S〜M に収める |

## 新しいエラーコード（E11xx 帯）

| コード | 内容 |
|---|---|
| E1101 | 未知の Effect 名（Phase 1 は `io` / `exit` / `pure` だけ。ヒントで一覧を示す） |
| E1102 | 呼び出し先の Effect を、呼び出し元の `uses` が宣言していない（足りない Effect を列挙する。`uses` に足す修正を示し、呼び出し先の定義を `related` に入れる） |
| E1103 | `uses` を書いた関数から、`uses` のない関数を呼んでいる（呼び出し先に `uses ...` か `uses pure` を付けるよう促す） |
| E1104 | `uses` の並びが正しくない（同じ名前の重複、`pure` とほかの名前の併記） |

警告は追加しない。`uses` の後に名前がないなどの構文の誤りは、既存の E0101 で報告する。

## 影響

- 実装を2つに分ける。
  - **T9a:** 構文（`uses` 節）、AST と `FuncSig`、組み込み関数の表、検査（E1101〜E1104）、Conformance、`grammar.ebnf`、`error-codes.md`
  - **T9b:** IR の属性と `dump-ir`、`wys explain` の `effects`、スキーマ、スナップショット、e2e
- 既存のプログラムは壊れない（注釈がなければ検査しない）。生成コードも変わらない（バックエンドのテストで確かめる）。
- 更新する文書:
  - `grammar.ebnf`（`uses` 節、ソフトキーワードの注記）
  - `error-codes.md`（E11xx 帯）
  - `explain-schema.json`
  - `docs/design/ir.md`（関数の属性。「今後」の項目を消す）
  - 用語集（Effect、`uses` 節、`pure`）
  - `docs/test-plan.md`、`docs/roadmap.md`
  - ADR 一覧と、未決定事項 5 の欄
- 初版の制限:
  - 注釈のない関数は、検査も推論もしない。注釈のある関数から呼べるのは、組み込み関数と、注釈のある関数だけ。
  - Effect は2種類で、利用者は定義できない。
  - `-> uses:` は、型名 `uses` として読む（ソフトキーワードにした結果。`type uses = ...` を定義していなければ E0203）。
- 見直し条件:
  - M4 で FFI を入れるとき（`python` / `ffi` の Effect）
  - M5 で AI SDK と Capability Runtime を入れるとき（`fs` / `net` / `llm`、`@tool` と宣言の突き合わせ）
  - M6 で推論を入れるとき（論点 4・5・7 の既定、E1103 の廃止、未使用の警告）
  - 関数値を入れるとき（Effect 多相）
