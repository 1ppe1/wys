# ADR-0005: メモリモデルはコンパイラ挿入の ARC と Move 最適化とする

- **状態:** Proposed
- **日付:** 2026-11-04（同日、設計レビューの指摘を反映して改訂）
- **関連:** 未決定事項 4、MEM-001〜006, NFR-001, `docs/design/memory-model.md`

## 背景

通常のコードで明示的な解放を書かずに済み（MEM-001）、安全なコードで use-after-free と二重解放が起きない（MEM-005）メモリ管理が必要。
同時に、Python 風の簡潔さ（P-01）と、予測可能な実行時コスト（P-07）を両立させたい。
要件定義書は「GCなし・完全自動・所有権チェックなし・任意の並列処理が安全」を同時に実現する前提にはしない、としている。

## 選択肢

`docs/design/memory-model.md` の5章を参照。要約:

- **案A: ARC + Move 最適化**（Swift / Nim ARC 型）
- 案B: トレーシング GC
- 案C: Rust 型の所有権・借用検査
- 案D: 案A に加え、高性能部分だけ明示的な借用・Move を書ける

## 決定

（ユーザーレビュー待ち）推奨は **案A**。理由:
- プログラマは所有権を意識せずに書け、P-01 と MEM-001 を満たす。
- GC の停止がなく、コストが retain / release の回数として測れる（P-07）。
- オブジェクトが移動しないので、FFI（CPython 連携、M4）でポインタを固定する必要がない。ただし CPython 側の参照カウントや GIL との整合は、別途 M4 で設計する。
- 案D（明示的な借用）は、後から案A の上に追加できる。

所有権の規則は `memory-model.md` 2.2 に従う。要点:
- ローカルのスロット、コンテナの要素、フィールドは値を +1 で所有する。store では古い値を release する。
- 引数は +0（借用）で渡す。ただし、**可変な場所から load した値を引数にするときは、呼び出し側が +1 を保持する**（借用の安全条件）。
- 文字列リテラルは不死オブジェクトとして扱い、retain / release の対象外にする。

保証範囲は `memory-model.md` 3章の表のとおりとし、**循環参照は MVP では回収しない**（`weak` 参照で回避する）と仕様に明記する。

## 影響

- IR に参照型、`retain` / `release`、+1 で消費するオペランドを追加する（M3）。
- オブジェクトのヘッダの配置は M3 で決める。それまで ABI は安定させない。
- 解放処理（drop グルー）は生成コード側に置く。ランタイムはメモリの確保・返却と組み込み型を担当する。
- **M3 の受け入れ条件に、Conformance テストを AddressSanitizer 付きで実行して問題が出ないことを加える。**
- 借用の安全条件は、Phase 2 で `async` を導入する前（M4）に再確認する。
- 循環参照によるリークを既知の制限として文書化し、M7 以降で循環回収器を評価する。
- 見直し条件: M3 のベンチで retain / release のコストが支配的になった場合や、循環参照の実害が大きい場合。そのときは案B（GC）をランタイムの選択肢として再評価する。
