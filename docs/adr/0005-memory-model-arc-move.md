# ADR-0005: メモリモデルはコンパイラ挿入の ARC と Move 最適化とする

- **状態:** Proposed
- **日付:** 2026-11-04
- **関連:** 未決定事項 4、MEM-001〜006, NFR-001, `docs/design/memory-model.md`

## 背景

通常のコードで明示的な解放を書かずに済み（MEM-001）、安全なコードで use-after-free と二重解放が起きない（MEM-005）メモリ管理が必要。
同時に、Python 風の簡潔さ（P-01）と、予測可能な実行時コスト（P-07）を両立させたい。
要件定義書は「GCなし・完全自動・所有権チェックなし・任意の並列処理が安全」を同時に実現する前提にはしない、としている。

## 選択肢

`docs/design/memory-model.md` の5章を参照。要約:

- **案A: ARC + Move 最適化**（Swift / Nim ARC 型）
- 案B: トレーシング GC
- 案C: Rust 型の所有権・借用検査
- 案D: 案A に加え、高性能部分だけ明示的な借用・Move を書ける

## 決定

（ユーザーレビュー待ち）推奨は **案A**。理由:
- プログラマは所有権を意識せずに書け、P-01 と MEM-001 を満たす。
- GC の停止がなく、コストが retain / release の回数として測れる（P-07）。
- FFI でオブジェクトが移動しないので、CPython 連携（M4）が単純になる。
- 案D（明示的な借用）は、後から案A の上に追加できる。

保証範囲は `memory-model.md` 3章の表のとおりとし、**循環参照はMVPでは回収しない**（`weak` 参照で回避する）と仕様に明記する。

## 影響

- IR に参照型と `retain` / `release` を追加する（M3）。IR 検証器に釣り合いの検査を加える。
- 引数は借用（+0）、戻り値は所有（+1）の規約とする。
- 循環参照によるリークを既知の制限として文書化し、M7 以降で循環回収器を評価する。
- 見直し条件: M3 のベンチで retain / release のコストが支配的になった場合や、循環参照の実害が大きい場合。そのときは案B（GC）をランタイムの選択肢として再評価する。
