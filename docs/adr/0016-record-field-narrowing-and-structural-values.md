# ADR-0016: 不変レコードのフィールドの絞り込みと、構造を持つ値の `print` / `==`

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** AC-002、LANG-003、LANG-005、LANG-006、DX-005、ADR-0006（絞り込みの対象）、ADR-0007、ADR-0009、ADR-0010、ADR-0011、ADR-0012、ADR-0013（論点 14）、ADR-0015（論点 9）、`docs/design/memory-model.md` 2.2・2.5・2.8、`docs/plans/m3.md` T10

## 背景

ADR-0006 では、絞り込みの対象をローカル変数と引数だけにした。フィールドは別名を通じて書き換えられるので、絞り込みが健全でないという理由だった。

しかし、本言語のレコードは不変である（ADR-0007）。M3 でも値型で、受け渡しのときにコピーされる（ADR-0009、ADR-0012 §1）。グローバル変数もクロージャもなく、関数は引数のレコードを書き換えられない。そのため、`p` を再代入しない限り `p.x` の値は変わらない。ADR-0006 の理由は、不変レコードには当てはまらない。M2 の最終レビューでも、「`if r.x is not None:` の後も `r.x` が Optional のまま」が既知の制限として残った。

同じ T10 で、M2・M3 から持ち越した次の項目も一緒に決める。

- レコード・`list`・`dict`・`Result` の `print` と `==`。いまは E0201 / E0207 になる。ADR-0013 論点 14 と ADR-0015 論点 9 で「T10 で見直す」とした。
- Generic 関数の `T | None` に `Unknown` を渡したときの `is None`。いまは通る。ADR-0011 の「絞り込みは `match` だけ」との関係を決める。
- `import ... as`。ADR-0010 で「後で追加できるようにしておく」とした。
- 未使用の変数と import の警告（W02xx 帯）
- `list` を経由する再帰レコード（E0504）

## 選択肢と決定

### A. 不変レコードのフィールドの絞り込み

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 1. 対象の経路 | 根がローカル変数か引数で、レコードのフィールド参照だけを連ねた経路（`p.x`、`a.b.c`）を対象にする。添字 `xs[i]`、`d[k]`、`d.get(k)`、関数やメソッドの呼び出しの結果は、引き続き対象外とする（ローカル変数に取り出してから検査する。E0301 のヒントでそう示す） | 添字も絞り込む | `list` / `dict` の要素は可変な場所で、別名から書き換えられる（memory-model 2.5）。ADR-0006 の理由がそのまま当てはまる |
| 2. 絞り込む構文 | 変数と同じにする。`is None` / `is not None`、`assert(...)`、`match 経路:` の型パターン・`None`・`_`、`and` / `or` / `not` との組み合わせ。代入による絞り込みはない（フィールドには代入できない） | `match` だけ | 変数と規則を揃え、AI が覚える規則を増やさない |
| 3. 健全性の根拠 | レコードは不変で（ADR-0007）、受け渡しはコピー（ADR-0009 / 0012）。根の変数を再代入しない限り、関数呼び出し・メソッド呼び出し・ループの反復でフィールドの値は変わらない。グローバル変数とクロージャはない。可変なレコードや `class` を入れるときは、この前提を見直す | — | 不変な値の部分は、根が変わらない限り変わらない |
| 4. 無効化 | 根の変数に代入したら（`p = ...`、`for p in ...`、`case Ok(p):` の束縛）、`p.` で始まる経路の絞り込みをすべて捨てる。ループでは、本体で代入される変数の経路を入口で捨てる（既存の規則の拡張）。分岐の合流は既存の規則に従う（両側に残っている経路だけを残し、型は和集合） | 再代入した後も残す | 根が変われば値も変わる |
| 5. 経路の途中の Optional | `a.b` が `B \| None` なら、先に `a.b is not None` で絞り込んでから `a.b.c` を読む（絞り込まずに読めば E0301。既存の規則）。絞り込んだ `a.b` の型をもとに `a.b.c` の型を決める | 自動で `None` を伝搬する（`?.`） | ADR-0006 で、`?.` は導入しないと決めた |
| 6. E0302 | フィールドの宣言型が `None` を含まなければ、変数と同じく E0302 にする | — | 既存の実装がすでにこの診断を出している |
| 7. `Unknown` のフィールド | `p.u`（`u: Unknown`）に `is None` を使うと、引き続き E0601 にする。`match p.u:` の `case int():` などで経路を絞り込める | — | ADR-0011（`Unknown` は `match` でだけ絞り込む）と整合する |
| 8. Generics | `T \| None` 型のフィールドにも同じ規則を使う。E0401（型パラメータへの型パターン）は変えない | — | 単相化の前に検査が完結する性質（ADR-0006）を保つ |
| 9. 診断と `explain` | explain の `narrowing[].variable` に経路の文字列（`p.x`）を入れる。スキーマの型は文字列のままにして、説明文だけを更新する（v0 の「項目の追加だけ」の範囲）。診断のメッセージにも、経路をそのまま出す | 経路用の項目を新しく作る | 契約を変えない |
| 10. 実装 | 流れ解析の環境のキーに、経路の文字列を使う。識別子に `.` は使えないので、変数と衝突しない。lowering では、`Field` 式の型が宣言型と違えば、変数と同じく値を変換する（Union から構成要素へは `UnionPayload`） | 環境を木構造にする | 既存の合流と無効化の処理をそのまま使える |

### B. 構造を持つ値の `==` / `!=`

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 11. 型の規則 | 比較できる組は次のとおり。`int` / `bool` / `str` どうし（従来どおり）。同じ定義のレコード型どうし。同じ `list[T]`、同じ `dict[K, V]`、同じ `Result[T, E]` どうし。Union は、片方の型がもう片方に置ける場合（`o: int \| None` の `o == 1`）。構成要素（フィールド、要素、payload）も再帰的に比較できる型であること。型パラメータ `T` 単独と、`Unknown` を含む型（E0601）は比較できない。`None` リテラルとの比較（`x == None`）は引き続き E0207 にし、ヒントで `is None` を示す | Python のように何でも比較できる | 比較できない型は静的に弾く（暗黙の変換をしない方針、E0207）。`== None` を禁じるのは、絞り込みを `is None` に一本化するため |
| 12. 意味 | 構造的に比べる。レコードはフィールドごと、`list` は長さと順序どおりの要素、`Result` と Union はタグと payload（`None == None` は真）、`dict` はキーの集合と各キーの値（順序は問わない。Python と同じ）。`!=` は `==` の否定。参照が同じかどうかは比べない | 参照の同一性で比べる | 値を中心とする言語として自然。`is` は `None` 専用のまま |
| 13. 幅部分型 | `==` では型を変換しない。定義の違うレコードどうしは E0207 | 共通のフィールドだけを比べる | 一部のフィールドだけを比べるのは、読み手の期待と違う |
| 14. 実装 | IR の `Eq` 命令が扱う型を広げる。バックエンドが、drop glue と同じ方式で型ごとの比較関数を生成する。ランタイムが持つのは `wys_str_eq` と `dict` の探索だけ。被演算子は借用で読み、参照カウントは変えない | ランタイムで汎用的に比べる | ADR-0012 §4（型の配置を知っているのは生成コード） |

### C. 構造を持つ値の `print`

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 15. 型の規則 | `print` が受け付ける型を、`int` / `bool` / `str`（従来どおり）に加えて、レコード、`list`、`dict`、`Result`、構成要素がすべて表示できる Union に広げる。トップレベルの `T \| None` は、従来どおり E0301（未検証の Optional の利用、AC-002）。構造の中の `None` は `None` と表示する。`Unknown` を含む型は E0601、型パラメータは E0201 のまま | トップレベルの `None` も表示する | トップレベルの Optional は、たいてい検査のし忘れ。構造の中の `None` はデータ |
| 16. 書式 | `list` は `[1, 2]`。`dict` は `{"a": 1, "b": 2}`（挿入順）。`Result` は `Ok(1)` / `Err("x")`。レコードは `P(x=1, y=2)`（型名と、フィールド名の辞書順。Generic のレコードは `Pair(first=1, second="a")` で、型引数は書かない。幅部分型で変換した値は、変換後の型の名前）。構造の中の `str` は `"` で囲み、`\"` `\\` `\n` `\t` `\r` `\0` をエスケープする。`bool` は `True` / `False`、`None` は `None`、空は `[]` / `{}`。トップレベルの `str` は、従来どおりそのまま出す | Python の `repr`（`'a'`）、JSON | 本言語のリテラルと同じ表記にして、読み返せるようにする。レコードはフィールド名の順に正規化して登録し、構造的に同じ定義は ID を共有するので、宣言順を持てない。名前順が、唯一の決定的な順序 |
| 17. 実装 | ランタイムに、改行しない書き出しの関数を足す。型ごとの表示関数は生成コードで作る。文字列を組み立てないので確保が要らず、ARC に影響しない | `str` に変換してから出す | 確保が要らない |

### D. Generic 関数と `Unknown`

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 18. `T \| None` への `Unknown` | 許して、仕様にする。`T = Unknown` と推論し、`T \| None` は `Unknown` に平坦化される（ADR-0006 の規則）。関数の本体は `T \| None` に対して検査するので、本体の `is None` は正当。`Unknown` の実行時表現は `None` のタグを持つ（ADR-0011）ので、インスタンスでも正しく動く。戻り値の `T` は `Unknown` のままで、呼び出し側は `match` でしか使えない（E0601）。次の意味を明記する: `Unknown` の `None`（`null`）は、`T \| None` の `None` と同じものとして扱う（`unwrap_or(parse_scalar("null"), 0)` は `0`） | 禁止する（新しい E04xx） | ADR-0011 の核心（`Unknown` は `match` でだけ具体的な型になる）は、呼び出し側で保たれる。外部の値に既定値を与える処理には需要がある。ADR-0011 は書き換えない |

### E. `import ... as`

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 19. 構文と意味 | `import a.b as c`（`c.f()` で参照し、`a.b.f()` は使えない）と、`from a.b import f as g`。`as` を予約語にする。別名が同じモジュールの定義や別の import と衝突したら E0704 | 入れない | Python と同じ。ADR-0010 の想定どおり |

### F. 未使用の警告（W02xx 帯）

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 20. W0201 | 代入されたが一度も読まれないローカル変数（`for` の変数、`case Ok(x)` の束縛を含む）。`_` で始まる名前は除く。引数は対象外（Phase 1）。読まれない再代入（`x = 1` の直後の `x = 2`）も対象外 | 引数にも警告する | 未使用の引数は、API の形を保つためによくある。AI の修正ループ（DX-005）では、意味のない警告は雑音になる |
| 21. W0202 | 使われない import（`import m`、`from m import f`、別名を含む） | — | モジュール解決が名前の参照を見ているので、安く作れる |
| 22. 扱い | 警告はビルドを止めない（既存の規則）。`wys test` も同じ | — | — |

### G. 見送るもの

| 論点 | 決定（推奨） | 理由 |
|---|---|---|
| 23. `list` を経由する再帰レコード | M3 では入れない（E0504 のまま。メッセージを「M3 では」に直し、`list` 経由も未対応だと示す）。M4 で、memory-model 2.6（`weak`、循環参照の方針）と一緒に決める | 理由は2つある。(1) レコードはフィールドの並びで構造的に登録しているので、自己参照には名目的な前方宣言が要る。型の深さ（E0404）、型パラメータや `Unknown` を含むかの判定、Generic な再帰型の展開、幅部分型の判定、IR の型登録をすべて見直すことになり、規模が大きい。(2) 不変レコードと可変な `list` を組み合わせると、`n.children.append(n)` のような循環参照を作れるようになる。ADR-0012 §5 の「M3 では循環参照を作れないので、生存数 0 を厳密な合否の基準にできる」が崩れる |
| 24. `fmt` の折り返し | 言語の意味に関わらないので、T10 の最後の任意作業にし、M3 の出口条件に含めない。残れば M4 に繰り越す | 出口判定の直前に、開発体験（DX）の不具合を抱えない |

## 新しいエラーコード

| コード | 内容 |
|---|---|
| W0201 | 代入されたが使われないローカル変数（`_` で始まる名前は除く。修正のヒント: 使わないなら `_` を付けるか削る） |
| W0202 | 使われない import |

既存コードの説明も更新する。E0201（`print` が受け付ける型）、E0207（`==` の規則、`== None`）、E0301（ヒントに「添字の値はローカル変数に取り出す」）、E0504（M3 でも未対応、`list` 経由を含む）。

## 影響

- 実装を次の順に分ける。
  - **T10a:** フィールドの絞り込み、論点 18 のケース
  - **T10b:** `==`
  - **T10c:** `print`
  - **T10d:** `import as`
  - **T10e:** W0201 / W0202
  - **T10f（任意）:** `fmt` の折り返し
- 更新する文書:
  - `grammar.ebnf`（`import` の `as`、予約語）
  - `error-codes.md`（W02xx と、上に挙げた説明）
  - `explain-schema.json`（`narrowing[].variable` の説明）
  - `ir.md`（`Eq` と表示の命令、生成する関数）
  - `memory-model.md` 2.8（絞り込みの根拠を1行）
  - 用語集（経路、未使用）
  - ADR 一覧（ADR-0010 / 0011 / 0013 / 0015 との関係）
  - `docs/plans/m3.md`、`roadmap.md`
- 見直し条件:
  - 可変なレコードや `class` を入れるとき（論点 3 の前提が崩れる。絞り込みは不変な型のフィールドに限る）
  - レコードの宣言順を保持するようになったとき（論点 16 の表示順）
  - `float` を入れるとき（`print` の書式）
  - 再帰レコードは M4 で扱う（論点 23）。引数の未使用の警告は、LSP（M6）で検討する。
