# ADR-0027: 正式名称・拡張子・パッケージ名と改名の範囲

- **状態:** Proposed
- **日付:** 2026-11-11
- **関連:** 未決定事項 1、LANG-001、ADR-0010（可視性。未決定事項 1 のうち可視性だけを決めた）、`docs/plans/release.md` T2 / T13、#71

## 背景

未決定事項 1 のうち、可視性の規則は ADR-0010 で決めたが、言語名・拡張子・パッケージ名は「公開前」に決めることにしていた。いまは内部コードネーム `wys` を、CLI の実行ファイル名、拡張子 `.wys`、環境変数の接頭辞 `WYS_`、クレート名 `wys_*`、ランタイムの C ABI シンボル（`wys_list_*` / `wys_rc_*` など）、ランタイムのファイル名（`libwys_runtime.a`）に使っている。用語集は `wys` を「正式な言語名ではない」と明記している。

改名の表面積（2026-11-11 時点）:

| 面 | 量 | 利用者に見えるか |
|---|---|---|
| CLI の実行ファイル名、使い方の文面 | `crates/wys_cli` | 見える |
| 拡張子 `.wys` | 514 ファイル（大半は Conformance） | 見える |
| 環境変数 `WYS_*` | 26 種 | 見える |
| ランタイムのファイル名 `libwys_runtime.a` / `libwys_runtime_python.a` | 配布物の `lib/` | 見える |
| LSP の `source: "wys"` / `serverInfo`、Markdown のコードブロックの言語名 | `crates/wys_lsp` | 見える（エディタ） |
| 文書・例・scripts / benches | docs に約 650 回 | 見える |
| クレート名 `wys_*` | 18 クレート | 見えない（`publish = false`） |
| ランタイムの C ABI シンボル、IR の名前（`@.wys.compiler` など） | ランタイムとバックエンド | 見えない（内部。安定性を約束しない） |

名前そのものはユーザーが決める（CLAUDE.md: 勝手に名前を付けない）。この ADR は、名前を決めたときに「何を、どこまで、どの順で」改名するかと、決め方を定める。

## 選択肢

### 案A: `wys` を正式名称にする

- 利点: 改名の作業がほぼない。既存の文書・設定例がそのまま使える。
- 欠点: 用語集にある由来の書き方を整理する必要がある。衝突の調査は別に要る。

### 案B: 新名称で一括改名

- 利点: 内部と外部の名前が一致する。
- 欠点: クレート名・ランタイムのシンボル・IR まで変えるので規模が L〜XL。スナップショットの全更新、回帰の危険が最大。利用者には見えない面の改名に価値が少ない。

### 案C: 新名称で段階改名（利用者に見える面だけ）

- 利点: 利用者に見える面は新しい名前で一貫する。内部の改名を避けるので規模は M〜L。
- 欠点: 内部名 `wys` が残る（コードを読む貢献者には見える）。内部名であることを文書で明記する必要がある。

## 決定

**案C を採る**（2026-11-11 にユーザーが方針を選んだ。名前は未定）。

1. **原則**: 拡張子 = CLI のコマンド名 = パッケージ名（配布物のアーカイブ名、将来のレジストリの名前）。小文字の ASCII。
2. **改名する面**（利用者に見える面）: CLI の実行ファイル名、拡張子、環境変数の接頭辞、ランタイムのファイル名、LSP の `source` / `serverInfo` とコードブロックの言語名、使い方の文面とエラーの文面、文書・例・scripts / benches、Conformance のファイル名、GitHub のリポジトリ名（ユーザーが変更する。旧名からのリダイレクトが残る）。
3. **改名しない面**（内部名として残す）: クレート名 `wys_*`、ランタイムの C ABI シンボル、IR の名前。`docs/stability.md`（ADR-0029）で「内部名であり、安定性を約束しない」と明記する。用語集の `wys` の行は「内部コードネーム（クレート名とランタイムの内部シンボルに残る）」に書き換える。
4. **環境変数の移行**: 新しい接頭辞だけを読む（0.y の間は互換を約束しない。ADR-0029）。旧い `WYS_*` を読む互換層は作らない（公開前なので利用者がいない）。
5. **衝突の調査**（ユーザーが行い、結果を下の表に記録する）: crates.io、PyPI、npm、Homebrew、GitHub の組織名・リポジトリ名、ドメイン、既存の拡張子の登録（Linguist など）、同名のプログラミング言語・商標。
6. **手順**（T13）: 改名は 1 本の PR で行い、`scripts/check-names.sh`（旧名が許可された場所以外に出たら失敗）を `scripts/ci.sh` に足す。3 モードの CI と Docker の Linux を必ず回す。スナップショットの差分をレビューしてから更新する。

## 影響

- 名前が決まるまで、文書は「本言語」と書き、配布の仕組み（T7）は名前を変数 1 か所に置く。
- 承認には上の表の記入が要る（方針だけの承認はしない）。承認したら、ADR 一覧の未決定事項 1 の欄を更新する。
- 見直し条件: 衝突の調査で問題が見つかったとき（名前を選び直す。この ADR の方針は変えない）。
