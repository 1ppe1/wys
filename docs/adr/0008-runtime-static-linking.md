# ADR-0008: ランタイムは Rust の staticlib として実行ファイルに静的リンクする

- **状態:** Accepted
- **日付:** 2026-11-04
- **関連:** 未決定事項 6、COMP-002, AC-004, ADR-0002, ADR-0004

## 背景

AC-004 は「指定したMVP対象環境で外部インタプリタなしに起動できる」ことを求めている。生成コードが呼ぶランタイム（出力、終了、実行時検査）をどう配布・リンクするかを決める必要がある。

## PoC1 の結果

- `crates/wys_runtime` を `staticlib` として作り、生成したオブジェクトと一緒に clang でリンクした。
- ランタイムは C ABI 関数（`wys_print_int` など）を公開する。宣言は `wys_backend` の `PRELUDE` と一致させている。
- 生成物の動的依存は `/usr/lib/libSystem.B.dylib`（macOS 標準）だけ。
- 実行時エラー（オーバーフロー、0除算）は stderr にメッセージを出し、終了コード 101 で終わる。

## 選択肢

### 案A: Rust staticlib を静的リンク（PoC1 で実装済み）

- 利点: 単独で動く実行ファイルになる。ランタイムを Rust で安全に書ける。
- 欠点: Rust 標準ライブラリを含むので、バイナリが大きくなる（Debug で約 1.4MB）。

### 案B: 動的ライブラリとして配布

- 利点: 実行ファイルが小さくなり、ランタイムだけを更新できる。
- 欠点: 実行時にライブラリの場所を解決する必要があり、AC-004 の「単独で起動できる」を満たしにくい。

### 案C: ランタイムを C で書く、または生成コードに直接埋め込む

- 利点: 最小のバイナリになる。
- 欠点: メモリ管理（M3 の ARC）を含むランタイムを、安全でない言語で書くことになる。

## 決定

案Aを採用する。

## 影響

- `cargo build` で `target/<profile>/libwys_runtime.a` が作られる。CLI は `WYS_RUNTIME_LIB`、次に自身の隣の順で探す。
- 実行時エラーの終了コード 101 は暫定。M3 でエラー処理（Result）と合わせて仕様にする。
- 見直し条件: バイナリサイズが問題になったら（M3 のベンチで計測）、`panic = "abort"` や `no_std` 化を検討する。
