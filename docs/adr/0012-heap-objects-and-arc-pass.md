# ADR-0012: ヒープオブジェクトと、IR パスによる ARC

- **状態:** Proposed
- **日付:** 2026-11-04
- **関連:** ADR-0005（ARC + Move）、ADR-0009（M2 の暫定値表現。この ADR が一部を置き換える）、`docs/design/memory-model.md`、`docs/plans/m3.md`、MEM-001/002/005、NFR-001

## 背景

M3 で `str` の連結、`list[T]`、`dict[K, V]` を入れるため、ヒープ上のオブジェクトを安全に解放する仕組みが必要になる。ADR-0005 はコンパイラが挿入する ARC と Move 最適化を決めたが、次の点が未定だった。
- オブジェクトのヘッダの配置（memory-model 2.4 は「M3 で決める」としていた）
- retain / release をどの段階で挿入し、どう正しさを確かめるか
- ADR-0009 の値型（レコード、Union）をどこまで参照型に移すか

## 決定

（ユーザーレビュー待ち。ARC を IR の独立パスで挿入することは、ユーザーが M3 計画の承認時に決定済み）

### 1. どの型をヒープに置くか

| 型 | 表現 |
|---|---|
| `str` | ヒープオブジェクトへのポインタ1語。今の `{ptr, len}` の2語は廃止する |
| `list[T]` / `dict[K, V]` | ヒープオブジェクトへのポインタ1語 |
| レコード、Union | **値型のまま**（ADR-0009 を継続）。ただし参照型のフィールドや構成要素を持てる |

レコードは不変なので、値型のままでもプログラムから見える意味は変わらない。参照型にしても retain / release が増えるだけで、M3 の完了条件には要らない。

### 2. ヘッダと不死オブジェクト

- ヘッダは `{ 参照カウント: i64, 長さ: i64 }` の2語。その後ろに中身（`str` はバイト列、`list` は要素の並び）を置く。
- 参照カウントが負のオブジェクトは**不死**で、retain / release は何もしない。文字列リテラルは参照カウント −1 の静的な定数として生成する。コマンドライン引数は起動時に不死オブジェクトにする。
- ABI はまだ安定させない（`weak` 参照の弱参照カウントと、循環回収器のためのビットは M4 以降に追加する）。

### 3. ARC は IR の独立したパスで挿入する

- lowering は所有権を意識せずに IR を作る。その後で `wys_ir::arc` パスが retain / release を挿入する。
- 各一時値に所有の種類を付ける: **+1 所有**（呼び出しの結果、新しく作った値）、**ローカルからの借用**（ローカルのスロットからの load）、**可変な場所からの借用**（`list` の要素などからの load）、**不死**（リテラル）。
- 規則は memory-model 2.2 のとおり。+1 で消費する地点（store、return、要素の追加）で足りない分を retain する。store では古い値を release する。関数を抜けるすべての経路で、解放が必要なローカルを release する。**可変な場所から借用した値を引数に渡すときは、呼び出しの前後で retain / release する**（借用の安全条件）。
- 冗長な retain / release の組の除去（Move 最適化）は、正しさを確かめた後の別段階（M3b）で入れる。

### 4. `list[T]` の要素と解放処理

- 要素は箱に入れずに並べる（`list[int]` は i64 の並び）。ランタイムは要素の大きさ付きのバッファ（確保、伸長、境界検査）だけを担当する。
- 要素や、レコード・Union の中の参照型の retain / release / 解放（drop glue）は、**生成コードが型ごとに関数として作る**。Rust のランタイムは型の配置を知らない（ADR-0008）。
- 解放が必要かどうか（`needs_drop`）と型ごとの関数は、型を登録するときに計算して表に持つ（深い型を再帰でたどると指数的になるため。M2 の教訓）。

### 5. 正しさの確かめ方

1. **IR の検証器:** ブロックの中で、+1 の値がちょうど1回消費されることを確かめる。
2. **デバッグ用ランタイムの生存数:** 確保と解放の回数を数え、プログラムの終了時に生存しているオブジェクトが 0 でなければ失敗にする。M3a では循環参照を作れない（可変なレコードも再帰的なレコードもない）ので、「リーク = コンパイラのバグ」として厳密な合否の基準にできる。
3. **AddressSanitizer:** 生成コードとリンクに `-fsanitize=address` を付けて、Conformance テストを実行する（ADR-0005 の M3 の受け入れ条件）。ASan が実際に検出できることも、わざと壊したテストで確かめる。

## 影響

- ADR-0009 のうち `str` の表現（不死の `{ptr, len}`）と「ヒープを使わない」は、この ADR で置き換える。レコードと Union の値表現は ADR-0009 のまま。M3 の出口（T11）で ADR-0009 を `Superseded by ADR-0012`（一部）とする。
- IR の型 `str` が参照型になり、命令 `Retain` / `Release` を追加する。`dump-ir` のスナップショットは変わる。
- ランタイムの C ABI は引き続きスカラーとポインタだけ（ADR-0009 の制約を継承）。
- 見直し条件: T3 の検査（生存数、ASan）で IR の設計変更が必要になった場合。retain / release のコストが問題になった場合は、M3b の Move 最適化と `explain` の計測で判断する。
