# ADR-0011: `Unknown` の実行時表現と検証 API

- **状態:** Accepted
- **見直し:** `list` / `dict` の種類と JSON の入力は ADR-0021 で決めた（2026-11-05、本文は Accepted のときのまま）
- **日付:** 2026-11-04
- **関連:** LANG-006、AC-003、P-02（境界での検証）、ADR-0006（`Unknown` の命名）、ADR-0009（ランタイム ABI はスカラーのみ）、`docs/plans/m2.md` T5

## 背景

LANG-006 は、未検証の外部値を `Unknown` 相当として扱い、明示的な絞り込み・検証を要求することを求めている。AC-003 の合格条件は「検証後のみ具体型として利用できる」こと。
M2 ではヒープを使わない（ADR-0009）ので、外部から入る値はコマンドライン引数と、その文字列を解釈したスカラー値に限る。JSON などの構造化データは、`list` や `dict` が入る M3 以降に扱う。

## 選択肢と推奨

| 項目 | 推奨 | 主な代替案 | 推奨の理由 |
|---|---|---|---|
| 実行時表現 | `int` / `bool` / `str` / `None` のタグ付き値（ADR-0009 の Union と同じ表現） | 文字列のまま持つ | 既存の Union のコード生成をそのまま使える |
| 型としての性質 | **開いた型**。`int \| bool \| str \| None` と同じ値を持つが、型検査ではそれとは別の型として扱い、検証するまで具体型として使えない | `int \| bool \| str \| None` の別名にする | 将来、取りうる値の種類（`float`、`list` など）が増えても、既存のコードが網羅的なままになってしまう事故を防ぐ |
| 絞り込みの方法 | **`match` だけ**（`case int():` など）。`Unknown` を `match` するときは **`case _:` を必須** にする（E0602） | `is None` や専用の検証関数も認める | 方法を1つにして、AI が生成するコードを単純にする。`case _:` 必須は「開いた型」の帰結 |
| 未検証の使用 | `Unknown` の値を、`Unknown` 以外を要求する場所（演算、`print`、具体型の引数や変数）で使うと **E0601** | — | AC-003 |
| `Unknown` への代入 | `int` / `bool` / `str` / `None` とそれらの Union は `Unknown` の場所に置ける。レコードは置けない | 何も置けない | テストやラップのしやすさ。レコードは表現が違う |
| 外部入力の入口 | `arg_count() -> int`、`arg(i: int) -> str \| None`（コマンドライン引数。範囲外なら `None`）、`parse_scalar(s: str) -> Unknown` | 引数を最初から `Unknown` で返す | 引数は「文字列であること」までは確実なので `str \| None` で返し、解釈を `parse_scalar` に分ける |
| `parse_scalar` の規則 | 10進の整数 → `int`、`true` / `false` → `bool`、`null` → `None`、それ以外 → `str`（入力そのまま） | Python の `True` / `None` 表記 | JSON のスカラーと同じ表記で、外部データとの相性がよい |
| ランタイム ABI | `wys_runtime_init(argc, argv)` を `main` の最初に呼んで引数を保存する。`wys_arg` と `wys_parse_scalar` は、結果を出力ポインタで返す | 構造体を返す | ADR-0009（ランタイムの C ABI にはスカラーとポインタだけを渡す） |

## エラーコード（T5 で実装）

| コード | 内容 |
|---|---|
| E0601 | 検証していない `Unknown` の値を使っている（修正ヒント: `match` で型を確かめる） |
| E0602 | `Unknown` の `match` に `case _:` がない |

## 決定

上表の「推奨」の列を採用する（ユーザー決定）。

## 影響

- `arg_count`、`arg`、`parse_scalar` は組み込み関数として追加する。M2 では、この3つが外部入力のすべてになる。
- Conformance テストに、プログラムに渡すコマンドライン引数を指定する `# expect-args:` を追加する。
- 見直し条件: M3 で `list` / `dict` と JSON の入力を入れるとき、`Unknown` の構成要素を増やし、検証 API（スキーマ検証、AI-002 と共通化）を設計し直す。
