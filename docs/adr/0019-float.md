# ADR-0019: `float`（IEEE 754 の倍精度、暗黙の変換なし）

- **状態:** Proposed
- **日付:** 2026-11-05
- **関連:** LANG-002、ADR-0006、ADR-0011、ADR-0013、ADR-0015、ADR-0016、ADR-0018（論点 9〜11）、`docs/plans/m4.md`（T12、T7）、issue #58

## 背景

いまの言語には `int` / `bool` / `str` しか数値と文字のスカラーがない。浮動小数点のリテラルは E0007（未対応）で、`int / int` は E0207（真の除算は未対応）にしている。M4 の計画では、Python の `float` を境界で受け取るために、T7（変換）の前に `float` を入れると決めた（ユーザー決定）。

決めることは次のとおり。

- 値の表現
- リテラル
- `int` との関係（暗黙の変換をしない、LANG-002）
- 演算と比較の規則（NaN、0 での割り算）
- 表示の書式
- `Unknown`（ADR-0011）と `parse_scalar` への追加

ADR-0011 は `Unknown` を開いた型にした。理由は「取りうる値の種類（`float` など）が増えても、既存のコードが網羅的なままになってしまう事故を防ぐ」ためで、`float` を足すことはこの時点で想定していた。

## 選択肢と決定

| 論点 | 決定（推奨） | 主な代替案 | 理由 |
|---|---|---|---|
| 1. 表現 | IEEE 754 の倍精度（binary64）の値型。LLVM では `double`、C ABI では 1 語。参照カウントはない | 32 ビット、任意精度の小数 | Python の `float` と同じ。値型なので ARC に影響しない |
| 2. リテラル | `1.5`、`0.25`、`1e10`、`1.5e-3`、`2E3`。小数点の前後には数字が要る（`1.` と `.5` は書けない）。指数だけの形（`1e10`）も `float`。丸めた結果が無限大になるリテラル（`1e400`）は E0009。`inf` / `nan` のリテラルはない（`float_inf()` などの関数も今は足さない） | Python と同じく `1.` と `.5` を認める | 小数点の両側に数字があれば、`xs.0` のような将来の構文や、範囲の `1..2` と混ざらない。無限大のリテラルは、たいてい書き間違い |
| 3. `int` との関係 | 暗黙の変換をしない（LANG-002）。`1 + 1.5` は E0207（ヒントで `float(1)` を示す）。変換は組み込み関数で行う: `float(n: int) -> float`（`int` から。2^53 を超える値は最も近い値に丸める）、`int(x: float) -> int`（0 の方向に切り捨て。NaN、無限大、`int` の範囲外は実行時エラー） | `int` を `float` に暗黙に広げる（Python） | 暗黙の変換をしない方針を守る。AI が生成したコードで、意図しない精度の喪失を型で見つけられる |
| 4. 演算 | `float` どうしの `+` `-` `*` `/` と、単項の `-`。結果は IEEE 754 のとおり（あふれは無限大、オーバーフローの検査はしない）。`/` は `float` だけ。`int / int` は E0207 のまま（ヒントを「`//` か、`float(a) / float(b)`」にする）。`float` の `//` と `%` は E0207（今は足さない）。**`float` の 0 での割り算（`x / 0.0`）は実行時エラー**（`runtime error: float division by zero`、終了コード 101） | (a) 0 での割り算も IEEE 754 のとおり無限大か NaN。(b) `int / int` を `float` にする（Python） | Python の利用者は `ZeroDivisionError` を期待する。`int` の 0 での割り算もパニック（ADR-0013）。あふれを無限大にするのは Python も同じ。(b) は暗黙の変換になる |
| 5. 比較 | `<` `<=` `>` `>=` `==` `!=` を `float` どうしに使える。IEEE 754 のとおりで、NaN はどの値とも等しくない（自分自身とも）。構造的な `==`（ADR-0016）でも同じなので、NaN を持つレコードは自分自身と等しくない。`float` は `dict` のキーにできない（E0907。ADR-0015 のキーは `int` / `bool` / `str` のまま） | NaN を等しいとみなす | Python と同じ。キーにすると NaN と丸めの問題を抱える |
| 6. 表示 | Python の `repr` と同じ書式。元の値に戻せる最短の 10 進表記で、整数の値なら `.0` を付ける（`1.0`、`0.1`、`2.5`）。指数が 16 以上か -5 以下なら指数表記（`1e+16`、`1e-05`）。無限大は `inf` / `-inf`、NaN は `nan`、負のゼロは `-0.0`。構造の中でも同じ（ADR-0016 論点 16） | C の `%g`、Rust の `{}` | 本言語の出力を Python の出力と突き合わせやすい。Python と同じ規則なら、AI が期待する出力と一致する |
| 7. `Unknown` と `parse_scalar` | `Unknown` が取りうる値に `float` を足す（実行時の表現の Union に構成要素が増える）。`match` では `case float():` で取り出す。`parse_scalar` は、JSON の数値の文法で小数点か指数を含む文字列（`"1.5"`、`"1e3"`、`"-0.5"`）を `float` にする。`"inf"` / `"nan"` / `"1."` は `str` のまま。既存の `Unknown` の `match` は `case _` が必須（ADR-0011）なので、網羅性の検査は壊れない | `float` を `Unknown` に入れない | ADR-0011 の開いた型の設計どおり。外部から来る数値（JSON、コマンドライン引数）を扱える |
| 8. その他の規則 | `float` は `print`・`==`・Union・`list` の要素・レコードのフィールド・Generic の型引数に使える。`len` / `range` には使えない。Effect はない。Python の境界では `float` と相互に変換する（ADR-0018 論点 10・11、T7） | — | 値型のスカラーとして、`int` と同じ場所に置ける |

## エラーコード

| コード | 内容 |
|---|---|
| E0007 | **廃止**（浮動小数点リテラル（未対応））。コードは再利用しない |
| E0009 | 不正な浮動小数点リテラル（丸めると無限大になる `1e400` など） |

`1.` と `.5` は、字句の上では `1` と `.` に分かれ、構文の誤り（E0101）になる。実行時エラーとして `float division by zero` と、`int(x)` の変換の失敗（`cannot convert nan to int` など）を足す。

## 影響

- 実装: 字句（`float` のリテラル、E0009）、型（`Ty::Float`、演算と比較の規則、`float()` / `int()`、E0207 のヒント）、IR（`Float` 型、定数、四則・比較・変換の命令）、バックエンド（`double`、`fdiv` の前の 0 の検査、比較は `fcmp`）、ランタイム（表示、`parse_scalar`）、`Unknown` の表現。
- 既存のプログラムは変わらない。`Unknown` の実行時の表現の Union に構成要素が増えるだけで、`case _` は必須なので、意味は変わらない。
- 更新する文書: `grammar.ebnf`（`FLOAT` の字句）、`error-codes.md`（E0007 の廃止、E0009、E0207 のヒント）、`docs/design/ir.md`、ADR-0011 の「取りうる値」の記述は書き換えず、この ADR を参照する（用語集と `docs/spec` で `Unknown` の値の一覧を更新する）、`docs/test-plan.md`。
- 見直し条件:
  - `float` の `//` と `%`、`inf` / `nan` を作る関数、数学関数（`sqrt` など）が要るとき
  - SIMD（Phase 3）で 32 ビットの浮動小数点が要るとき
