# ADR-0006: Union / None / Generics / エラー処理の構文

- **状態:** Proposed
- **日付:** 2026-11-04（同日、設計レビューの指摘を反映して改訂）
- **関連:** 未決定事項 3、LANG-003, LANG-004, LANG-006, LANG-008, NFR-007, AC-002, AC-003, ADR-0007

## 背景

LANG-003/004 は Null 安全性、Union 型、Generics、パターンマッチと網羅性検査を求めている。
構文は Python 利用者になじみがあり、AI が生成しやすく、型検査で検証しやすいものにしたい。
要件定義書 12 章の構文イメージは非規範的なので、ここで初めて構文を決める。

## PoC2 の結果（`crates/wys_typeck/src/experimental/narrowing.rs`）

- `if x is None: return` の後で `x` を `T` に絞り込む流れ解析は、PoC1 の確定代入解析と同じ「環境を流す」構造で実装できた。
- 分岐の合流で型を和集合に戻すこと、再代入で絞り込みを解除することも確認した。
- Union に対する `match` の網羅性検査（足りない構成要素の列挙）と、到達しない分岐の検出を実装できた。

## 選択肢と推奨

| 項目 | 推奨 | 主な代替案 | 推奨の理由 |
|---|---|---|---|
| Union / Optional | `int \| str`、`str \| None`。Union は平坦化する（`(T \| None) \| None` は `T \| None`） | `Optional[str]`, `str?` | Python 3.10 以降の型ヒントと同じ |
| None の検査 | `if x is None:` / `if x is not None:` による絞り込み | 専用演算子（`?.`, `??`, `!!`） | Python と同じ書き方で、PoC2 で流れ解析が可能と確認した |
| 絞り込みの対象 | **ローカル変数と引数だけ**。`self.x is not None` のようなフィールドやコンテナ要素は絞り込まない（ローカル変数に取り出してから検査する） | フィールドも絞り込む | フィールドは別名を通じて書き換えられるので、絞り込みが健全でない |
| パターンマッチ | `match x:` / `case int():` / `case None:` / `case _:` | 独自構文 | Python 3.10 の `match` に合わせる。網羅性の不足はコンパイルエラーにする |
| `case` で区別できる型 | プリミティブ型、`None`、名目的な型（`class` / `enum`）。構造的レコードは不可（ADR-0007） | — | 構造的なパターンは複数のレコード型に当てはまり、区別できない（PoC2 で確認） |
| Generics | `def first[T](xs: list[T]) -> T:`、`type Pair[A, B] = ...` | `TypeVar` 方式 | Python 3.12 の PEP 695 構文。宣言が局所的で、AI が生成しやすい |
| Generics の実装 | 単相化（monomorphization）。**型パラメータに対する `case int():` は禁止**し、網羅性検査を単相化の前に完結させる | 型消去 | ネイティブ性能（COMP-002）を優先する。単相化の後で型エラーが出ることを防ぐ |
| エラー処理 | `Result[T, E]` 型と、伝搬用の後置演算子 `?` | 例外（`try` / `except`） | 失敗を型で表す（LANG-008、NFR-007）。例外は FFI 境界で `Result` に変換する（AC-010） |
| `?` の適用範囲 | **`Result` だけ**に使える。`T \| None` には使えない。エラー型は、関数が宣言したエラー型に収まる場合（同じ型、または `E1 \| E2` の構成要素）だけ伝搬できる | `T \| None` にも使える | 意味を1つに保つ |
| `?.` / `??` | **導入しない**。None の扱いは絞り込みで書く | 導入する | `x?.y` が「`Result` を伝搬してから属性を参照する」とも「None 安全な属性参照」とも読めて、`?` と衝突する |
| `Unknown` | `Unknown` 型。`match` または検証関数でのみ具体型に絞り込める | `Any` | `Any` は検査を無効にする印象が強い。LANG-006 の「明示的な検証」を名前で示す |
| 実行時エラー | 整数オーバーフロー・0除算・境界外アクセスなどは `Result` ではなく**パニック**（プロセスの終了。終了コードは ADR-0008 の暫定値 101） | すべて `Result` にする | 回復を想定しないプログラムの誤りと、想定内の失敗（`Result`）を分ける |

## 決定

（ユーザーレビュー待ち）上表の「推奨」の列を採用する。

## 影響

- 構文はなるべく Python の型ヒントと同じにする。違う点（`?` 演算子、`Unknown`、網羅性エラー、絞り込みの対象の制限）は言語仕様で明示する。
- `T | None` の値表現は `memory-model.md` 2.7 に従う。
- パニックの扱い（メッセージ、終了コード、スタックトレースの有無）は M3 で仕様にする（NFR-007）。
- 見直し条件: M2 の実装で、Python の `match` 構文との違いが利用者を混乱させると分かった場合。
