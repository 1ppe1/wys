# ADR-0003: MVP の対象環境を macOS arm64 とする

- **状態:** Proposed
- **日付:** 2026-11-04
- **関連:** 未決定事項 7、NFR-006、AC-004

## 背景

NFR-006 は「MVPのサポートOS/CPUを明示し、CIで継続検証する」ことを求めている。
開発体制は1名＋AIで、開発機は macOS arm64。最初から複数の環境を対象にすると、環境差分の調査に時間を取られる。
（未決定事項7の後半「初期標準ライブラリ範囲」は、このADRでは扱わない。M3 で別のADRとして決める。）

## 選択肢

### 案A: macOS arm64 のみで始め、Linux x86_64 を後から追加する

- 利点: 開発機ですぐに検証できる。既にある clang を使って、バックエンドの比較（PoC1）をすぐに始められる。
- 欠点: Linux 固有の問題（リンカ、libc）の発見が遅れる。

### 案B: Linux x86_64 を優先する

- 利点: サーバー用途に直結する。
- 欠点: ローカルでの検証にコンテナが必要になり、開発ループが遅くなる。

### 案C: 最初から両方を対象にする

- 利点: 移植性を早い段階で担保できる。
- 欠点: PoC の負荷が増える。

## 決定

（ユーザーレビュー待ち）案Aを推奨する。Phase 1 の最初の対象環境は **macOS arm64（aarch64-apple-darwin）** とする。
**Linux x86_64（x86_64-unknown-linux-gnu）** は、M1 完了後に Conformance テストが安定してから、M2 で CI に追加する。遅くとも Phase 1 の出口（M3）までに追加する。
Windows は Phase 3 以降に検討する。

## 影響

- CI は M0 では macOS arm64 ランナーだけで動かす。
- Linux を追加するときは、バックエンド方式（ADR-0004）とランタイムのリンク方式（ADR-0008）が両方の環境で動くことを確認し、このADRの「影響」欄に追記する。
- AC-004 の「指定したMVP対象環境」は、この決定が Accepted になった時点で macOS arm64 を指す。
