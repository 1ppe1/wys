# PoC5: AI 修正ループの成功率（DX-005）

- **状態:** 準備済み・**未計測**（計測はユーザーが `scripts/poc5/run.sh` で行う。モデルを呼び出すため費用がかかる）
- **関連:** DX-005、UC-04、要件定義書 5.1（DX の評価軸）、`docs/plans/m2.md` T9

## 目的

コンパイラの構造化診断（診断 JSON）とテストの出力だけを手掛かりに、AI が壊れたプログラムを何回の試行で直せるかを測る。
M2 時点の初期値として記録し、診断のメッセージや修正ヒントを改善したときに比較する。

## 方法

- ケース: `scripts/poc5/cases/` の20件。コンパイルエラー15件（E0201、E0301、E0206、E0207、E0303、E0204、E0202、E0205、E0502、E0501、E0601、E0602、E0702、E0211 など）と、ロジックの誤り5件。
- 各ケースは `lib.wys`（直す対象）、`main_test.wys`（変更してはいけないテスト）、`fixed.wys`（正解の修正例）からなる。`scripts/poc5/verify.sh` が「壊れた版は失敗し、正解版は合格する」ことを確かめる（CI でも実行）。
- 試行: `wys test --format json main_test.wys` の出力を添えて `claude -p` に修正を依頼する。使えるツールは Read と Edit だけ。最大 K 回（既定3）。`main_test.wys` が変更されたら失敗として扱う。
- 指標: K 回以内に `wys test` が合格したケースの割合と、必要だった試行回数。
